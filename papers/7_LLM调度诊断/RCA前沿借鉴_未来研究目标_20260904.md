### G4 agentic 臂设计（P2 后半，方法论 §5 agentic 臂细化；2026-09-04 按 POMDP 建议扩充）

- **形式化二选一**：active diagnosis / POMDP（状态 s 不可观测，工具调用=主动观测
  o_t=Tool(a_t)，belief b_t=P(s|o_{1:t},a_{1:t})）与贝叶斯诊断循环
  P(H_i|E_{1:t}) ∝ P(E|H_i)P(H_i) 是同一形式——论文写作时取一套记号，不叠两套；
- **ability vs policy 二分**：工具语法/语义（query_event 怎么调）prompting+SFT 即可；
  "何时查/查什么/查几次/何时停"是序贯策略问题，才是学习阶梯的目标——
  这个区分本身写进论文 §4；
- 工具调用二分类：hypothesis-testing vs exploratory，报占比与序列模式；
- 新过程指标 **evidence-efficiency** = 达到正确诊断的最少工具调用数
  （= tool-use policy 的直接测量），与 MTTI/工具覆盖率并列；
- **Step 0 frozen agentic 先行**：schema + system prompt + few-shot ReAct 轨迹即可起步，
  零训练；single-shot vs agentic frozen 的结果就是 Q1 的答案；
- 落点：方法论 v0.2 §5 agentic 臂、论文 §4 架构 (b)；与 RCAgent §3 精读（T2 队列）一并定稿。

### G5 训练阶梯 v2 与下一篇接口（P3/P4；2026-09-04 重构）

**阶梯：Prompting → ReEvo 反思（training-free）→ SFT → DPO → GRPO**。
前三级属当前论文的反哺段，SFT 起属下一篇（Q2）主轴：

1. **SFT**：simulator 自动产 expert trajectories（与 Generator–Executor–Verifier 同构：
   教师可全知、verifier 过滤错误轨迹），三条设计约束：
   - **教师轨迹分档**：easy 档规则式展开即可；hard 档必须含统计签名探查轨迹
     （查 wait_ratio/阻塞/振荡而非事件表）——否则 SFT = 模仿规则基线，
     恰好把基准证明会塌陷的策略教给学生；
   - **防泄漏**：学生侧工具层不得暴露场景配置/故障参数；教师全知是出题人特权
     （方法论 §6 不对称的复用）；
   - **信息最小化**：教师轨迹按最少查询写，防止冗余查询泄漏答案位置。
2. **DPO**：同案例**轨迹级**配对 (τ, π⁺, π⁻)，用 R 打分取优劣——比稿子现在的
   "仅干预偏好对"更宽；注意长度偏置：惩罚项先并入 R 再配对，同案例控制其他变量。
3. **GRPO（可选终点）**：R = 2R_JRA + R_faith + η·clip(ΔKPI) − λ_tool·N_tool − λ_inv·N_invalid，
   组内归一化 advantage 免 critic。**两个工程前提**：
   - CRN 确定性 → 工具响应是 (case, tool, args) 的**纯函数** →
     Cloud-OpsBench 式状态快照 + 预计算响应缓存，rollout 成本首轮后坍缩——
     这是 GRPO 可负担的关键，不是锦上添花；
   - **成本项防退化**：λ_tool·N_tool 不是效率美学。没有它，"枚举药房词表当诊断探针"
     （挨个 submit_intervention 看 ΔKPI）是最优退化策略；且一次干预判分 = ≥30 seed
     重仿真，λ_tool 必须反映真实算力。
4. **奖励权重纪律**：权重是超参，预注册；报告按 R_JRA / R_faith / ΔKPI / 成本分解报
   （三判分器天然支持），不报单一标量。
5. 旧 G5 项保留为下一篇候选：**LLM 先验 + 统计因果发现**（LLM 给 Granger/NOTEARS 供先验边，
   引擎重仿真验证边）；**OpenRCA2 PAVE 过程 GT 引擎域移植**（注入参数程序已知 →
   cases_v3 产路径可达性过程真值）。Q2 立项时三者择一或组合。
