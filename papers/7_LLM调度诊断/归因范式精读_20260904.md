# 归因范式精读：RCA/验证/反事实文献的可借鉴机制（2026-09-04）

> 基于 papers/txt/ 下 15 篇全文精读（两路并行：RCA 归因范式 8 篇 + 验证/反事实协议 7 篇）。
> 前置文档：`前沿调研_20260903.md`。用户已确认：LLM 走特定 pipeline 产出四元组 = 创新点1，
> 一二三级（frozen→反思精化→反事实DPO）为探索阶梯，全程消融。

## 一、归因范式的三种输出哲学（领域现状）

| 范式 | 代表 | 适用条件 |
|---|---|---|
| **分类**（根因类别标签） | RCACopilot(EuroSys'24)、LogReasoner | 故障高复发（93.8% 故障 20 天内复发）、词表稳定 |
| **定位+机制**（⟨组件,类型⟩/⟨组件,原因,时间⟩） | CloudOpsBench、HowFar_RCA | 当前主流 |
| **因果链**（根因节点+传播路径+证据） | mABC(EMNLP'24)、OpenRCA2 | 过程监督的前提，最严格 |

推理机制已收敛为**"假设-取证-验证"循环**：结构化先验缩小空间 → 工具迭代取证 →
反思/投票/聚合。先验来源之争：HowFar 实证 mined-DK(35.9) > curated-DK(24.4) > 无DK(14.1)
——知识注入是最大可控增益。

**我们的四元组属于"定位+机制+因果链"混合**，与主流兼容且更严格（多了干预维度）。

## 二、过程监督（最重要的新认知）

**结果对 ≠ 链路对**，两篇 2026 基准给出打脸数据：
- CloudOpsBench：联合结果准确 JRA 0.76 vs 证据链正确率 ECR **0.38**
- OpenRCA2：AnySvc 76% vs 过程可达率 PR **61.5%**——差值就是"无接地诊断"

两套可操作的过程 GT 方案，我们引擎域做起来比云域便宜得多：
1. **里程碑证据图**（CloudOpsBench）：每案例标注原子诊断事实+可互换组+DAG 前置+证据束，
   评 MC/EOC/ECR 而不规定工具序列；
2. **PAVE 前向验证**（OpenRCA2）：利用 do(注入) 记录前向重构"扰动→拥堵→饥饿→KPI"
   验证链作过程 GT；要求定位对象到异常 KPI **路径可达**，Node F1 / Edge F1 分开报，
   专防"答对机器、链路编造"。

## 三、对四元组各维的具体借鉴

- **定位**：pass@1 严格匹配 + ITBench 式拓扑感知部分分 NTAM（预测根因与 GT 在
  工序-机器-AGV 拓扑上的距离，罚链长失配）；多根因用 mABC 惩罚式得分
  RA=(Ac−0.1·Ai)/At。
- **归因**：词表外加 **Unseen/计划外逃生舱**（RCACopilot 的 Unseen incident 选项），
  防强行归类；严格指标用 JRA 式"定位∧归因同时对"。
- **证据**：证据锚定（引用 fuzzy-match 回事件流/修订账本原文，不匹配即丢弃）+
  statement 级忠实度（见 §五）。
- **干预**：DT 闭环（LLMDigitalTwin）——先过校验脚本+cost 函数，失败把结构化
  violations 回灌 reprompt，设最大迭代数，**reprompt 次数本身报告为可靠性指标**。

**模态分工**（LLM_RCA_Failures）：metrics 主用于定位、logs 主用于类型判定 →
我们：KPI 轨迹做定位、事件流/修订账本做归因；"无事件"的沉默本身要作为信号喂给模型。

## 四、失败模式清单（我们自己评测里要预防的）

1. **salience capture / presence bias**（OpenRCA2）：最响的下游信号抢注意力、沉默的
   故障源被读作正常。对策：内置"**最早 onset 优先、受害者须有上游异常**"筛选规则；
   agentic 版做假设多样化+信念更新检查（anchoring 是最强负向预测 RR<0.55）。
2. **粒度失配=全零**（HowFar）：输出粒度与 GT 粒度不一致时全错——8 类词表必须覆盖
   全部注入故障空间；时间戳/原因维度单列评。
3. **traces 可能是干扰**（LLM_RCA_Failures）：移除部分遥测后准确率反升 →
   我们做"信息量-诊断准确率"曲线（对齐 DynaSchedBench observability paradox）。
4. **agentic 结构对小模型负收益**（LLM_RCA_Failures）：低于随机——主系统 vs 单轮
   消融的对照正好量化此权衡；弱模型配极简语义工具（RCAgent：SQL 式裸工具 invalid 率 70.9%）。

## 五、重仿真验证规范（LLMHeurFromTraces + LLMDigitalTwin 提炼）

- **Seed 协议**：搜索期各候选用独立 seed 集（防过拟合）；终评用公共 matched seed 集
  （连续 100 seed），所有方法同 seed 重仿真取配对差；双侧 Wilcoxon signed-rank +
  Holm 校正；报配对差中位数+分布图。
- **验收**：best-so-far（严格优于 incumbent 才替换，默认保留旧者）；no-improvement
  patience=3 早停；整个优化独立重复 ≥5 次。
- **报告口径**：优化期均值 + matched-seed 独立复核**双口径**；失败记 ΔKPI=−∞ 不丢弃；
  补 MTTD/MTTR 式时间指标与 token 成本。

## 六、Hard 案例（真 abduction）构造规范（ExecutableCounterfactuals + CounterBench）

1. **真 abduction**：隐藏故障参数（如堵塞程度），只给 KPI 轨迹——先反推隐变量再预测。
   全信息题会退化为 interventional（模型近乎满分；藏变量后掉 25-40%）。
2. **可辨识性验证**：设计上验证"改动隐变量必改变答案"才收题；不可唯一辨识时按
   多解集合评分（EM + set-F1）——防"题目本身有歧义"的审稿批评。
3. **CF−INT 配对对照**：同一仿真配对出 interventional 版（公开隐变量），报告 CF−INT
   差距，证明难度来自 abduction 而非题面。
4. **去先验**：场景/变量名 nonsense 化，答案分布均衡防基线虚高。

## 七、忠实度 statement 级评分（CorrectnessNotFaithfulness 改造）

定义：引用 (s,a) 忠实 = a 可查 ∧ a 支持 s ∧ s 因果依赖于 a。操作化：
1. 支持性：NLI 式 judge 判片段是否蕴含 statement；
2. 因果性：对抗注入——把结论关键词植入无关假记录后重查，转引假记录即判
   post-rationalization；或删改被引片段重问，结论应随之改变；
3. 指标：faithful citation rate（忠实引用/总引用），statement 级平均。

## 八、对二级训练阶梯的修正

- **反思精化照 ReflecSched**：不做自由反思，喂 **contrastive 证据**——同 seed 下
  采纳/不采纳的 ΔKPI best/worst 对，结构化输出 CONFIRM/CONTRADICT/ADD NUANCE 并
  合成单一原则；消融须含噪声经验组（证明 not all reflection 有益）；事件驱动触发省 token。
- **DPO 听 ExecutableCounterfactuals**：SFT 蒸馏不泛化、可验证奖励泛化——偏好对取自
  "同案例通过/未通过重仿真验证"的 on-policy 干预建议对；训练/评测结构上 OOD 分离
  （不同故障类型），报 ID+OOD 双成绩。

## 九、落地为实验设计的增量清单（相对 20260903 版）

1. 指标系增加：过程层（证据链正确率 ECR 式 / 路径可达 PR / Node-Edge F1）、
   NTAM 拓扑部分分、惩罚式多根因得分、MTTD/MTTR、reprompt 次数；
2. 场景库增加：CF/INT 配对版案例（同案例公开/隐藏故障参数）、Unseen 故障类型留出集
   （OOD 评测+逃生舱评测）、噪声经验消融组；
3. 案例标注增加：里程碑证据图（原子事实+DAG 前置）——我们有 do(注入) 记录，
   半自动生成可行；
4. 失败分析增加：反向推理归因（Reasoning Gap vs Data Ambiguity）→ 反哺 prompt 规则。
