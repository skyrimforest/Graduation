# 方法论 v0.2：数据生成、数据采集与答案生产规范（2026-09-04）

> 目标：把"LLM 诊断层"的方法论钉死到照着就能实现的程度。对应论文 §3 任务定义 / §4 数据集 / §5 评测协议。
> **v0.2 增补**：① KPI 观测三级粒度阶梯（+L4 神经显著性引导档，扩展臂）；② hard 视图三道质检防线
> （签名复验/可辨识性/CF−INT 兜底）；③ 信息二维网格（粒度×预算）与四臂对照。
> 背景：hard 孪生"只留统计特征"存在签名被摘要抹平的风险（ExecutableCounterfactuals 的
> 不可辨识陷阱），质检必须落在 hard 视图本身而非完整数据。

## 0. 一句话方法论

数据 = 引擎受控注入生成的（带证据ID的运行档案, 标准答案）对；
答案 = LLM 在受控词表约束下输出的四字段 JSON；
可信度 = 三个独立程序化判分器（比对 / 回查 / 同seed重仿真），全程零人工标注。

## 1. 数据生成（不是采集，是制造）

**一条数据 = 一次仿真运行。** 五步全自动：

1. **场景定义**：网格抽样 `(实例 mk01-mk05, 策略 ∈ {cpsat-full, greedy-reactive, cpsat-static, cpsat-partial}, K ∈ {3,4,6}, seed, 故障类型 ∈ 8类, 故障参数: 目标id × 时刻 × 时长)`。
   故障目标**随机化**（修复 v1 永远 0 号机的退化）；无事件类（活锁/瓶颈/计划失配）以运行配置触发（地图类型/K 压力/修订触发策略）。
2. **运行**：引擎跑一个 episode，自动记录全程指标/事件/修订账本（引擎审计工件，本来就有）。
3. **标注（零成本）**：ground truth 从场景定义程序抄取；无事件类用程序判据
   （饥饿活锁 = 任务池非空 ∧ 全 AGV 空转持续 N 步；走廊拥塞 = 阻塞延迟签名）。
4. **打包（v0.2：粒度阶梯化）**：轨迹 → 带证据 ID 的档案。KPI 观测按**三级粒度阶梯**为同一案例
   生成多个视图：**L1 原始轨迹**（逐段 KPI 曲线）/ **L2 分段摘要**（均值/峰值/拐点，每段带 ID，
   ≤8k token，默认档）/ **L3 标量汇总**（全段均值/极值）。事件表、修订账本、配置各级照常附带。
   **hard 孪生 = 删除 events 字段后的对应粒度视图**（easy 考阅读，hard 考推断，题目相同）。
5. **hard 视图质检（v0.2 三道防线，不过即拒收，不进案例库）**：
   - **签名复验**：核验器在 hard 视图（而非完整数据）上复验该故障的判别性统计量仍存在且可辨识；
     签名被摘要抹平（如活锁振荡被均值平滑掉）→ 拒收；
   - **可辨识性**：验证"改动故障隐变量必改变 hard 视图观测"才收题（照 ExecutableCounterfactuals 规范）；
     多个故障在 hard 视图不可区分 → 拒题，或降级为多解集合评分（EM + set-F1）；
   - **CF−INT 兜底归因**：每案例配一个 interventional 版（公开故障参数），报 CF−INT 差距——
     即使 hard 档全员考砸，也能把难度归因到 abduction 本身而非题出坏。
   ⚠️ **回溯义务**：P1 的 cases_v2（104 案例）签名确认是在完整数据上做的，须按本节在 hard 视图上
   重新复验一轮，被拒案例移出正式集（可留作 L1 档使用）。
6. **L4 显著性引导档（v0.2 扩展臂，不进 P2 关键路径）**：在 L2 档案上叠加**神经显著性指针**——
   小型序列模型（LSTM/TCN 自编码器）在无故障基线轨迹（P1 的 34 条 baseline）上无监督训练，
   推理时输出重构误差热点 ⟨KPI 项, 机器/AGV, 时间窗, 偏差倍数σ⟩。角色是"指路人"——专打
   "从上千解释中找对先看哪个统计量"这一瓶颈（§6.2），非"打包工"。**两条硬约束**：
   - **只指不证**：指针仅决定上下文排序/标注，指向的必须是档案中已存在的证据 ID 与数值；
     LLM 引用对象仍是原始条目（隐向量不可引用，忠实度判分不被旁路）；
   - **不进主链**：主消融链路保持纯手工 L2 档案，L4 仅作对照臂挂载——防"增益来自特征
     提取器而非 LLM 诊断"的混淆。
   已知弱点即实验点：神经检测对 Unseen 故障类型天然弱（重构误差只对训练分布敏感），
   在 Unseen 留出集上量化之，与 LLM 的 unseen 逃生舱行为对照成表。

**规模**：≥200 条，8 类归因每类 ≥25，外加 Unseen 留出类（训练/评测 OOD 分离）。

## 2. 数据采集（仅两处，均自动）

- 引擎运行轨迹（审计工件）；
- LLM 回答存档（内容/耗时/token 数/重生成次数）→ results jsonl。
- 没有爬虫、没有人工标注、没有外部数据。

## 3. 答案生产（具体到调用）

**输入**（一次 LLM 调用）= 固定格式 prompt：
```
[系统提示] 调度诊断专家。输出严格 JSON：
{"localization": <定位词表>, "cause": <归因词表+unseen>,
 "evidence": [<档案中的证据ID>,...], "intervention": <药房词表>,
 "narrative": "<只允许使用 evidence 引用过的事实>"}
硬约束: 不得引用档案中不存在的 ID 或数值; 不确定时降置信度。
[档案] <第1步打包的 JSON>
[查询] <如: 为何该 episode 的 makespan 超预期？定位关键资源与原因，给干预建议。>
```

**输出示例**：
```json
{"localization": "machine:3", "cause": "disruption_machine",
 "evidence": ["EVT001", "KPI:queue_wait_m3[150-210]=42", "CFG:K=4"],
 "intervention": "fleet(K=5)",
 "narrative": "3号机150步停机60步，其队列等待升至42分钟，AGV等待同步升高，完工推迟130步。"}
```

格式解析失败 → JsonRegen（转写 YAML 再重生成，循环至可解析）；答案阶段 TSC 采样 10-20 条聚合；temperature 0。

**词表三张表（与引擎/答案严格对齐）**：
- 定位: machine:<id> | agv:<id> | machine:<id>+agv:<id> | stochastic | task_pool | corridor | machines | none
- 归因: disruption_machine | disruption_machine_agv | disruption_stochastic | starvation_livelock | blocking_livelock | machine_bottleneck | plan_mismatch | baseline | unseen
- 药房（已核引擎支持）: padding(α∈{0.1,0.2,0.3}) | fleet(K±1) | periodic_revision(T) | assigner(name) | none
  （watchdog/machine_reroute 引擎未实现，v1 剔除）

## 4. 判分（三层，全程序化）

| 输出 | 判法 | 指标 |
|---|---|---|
| 定位/归因 | 与 ground truth 字符串比对（+拓扑近似部分分 NTAM 式；多根因惩罚式得分） | 定位准确率、归因准确率、JRA（两者同时对） |
| 证据 | 逐条回查档案（ID 存在 ∧ 数值一致）+ 对抗注入测试（塞假证据看是否被引） | 忠实度 = 通过条数/总条数 |
| 干预 | 解析 → 改配置 → **同 seed 重仿真** → ΔKPI（报告配对差+Wilcoxon，≥30 seeds） | 干预成功率 P(ΔKPI≥δ)、无效干预率、reprompt 次数 |

## 5. 对照设计

- 规则基线（已有，同 diagnose(case) 接口）vs LLM（easy 预期打平，hard 分胜负）
- 单轮打包 vs agentic（同一数据底座两种观测视图；引擎做成 5-6 个查询工具）
- 有/无接地约束 A/B；easy/hard/INT 三档；Unseen 留出集
- 信息二维网格（v0.2）：**粒度阶梯（L1 轨迹 / L2 分段 / L3 标量 / L4 神经引导）× token 预算（4k/8k/16k）**，
  "观测形态"与"信息量"各走一档——两端（看不出来 / 看得太多）都有数据点可写；
  L4 档直接对话 observability paradox：若"指针过滤后的少信息"优于全量档案，即 H4 最硬证据
- **第四类选手（v0.2）**：无 LLM 的神经异常检测器（L4 模型单独作答）作为附加基线——
  对照面扩为 规则基线 / 神经检测器 / LLM / LLM+L4 指针 四臂（anomaly detection 是 RCA 文献标准基线）

## 6. 标签与验证的不对称性（回应"标签不也是规则产的"）

**两种规则角色必须分开**：
- **出题人**：注入条件本身（我们造的病，答案由构造为真，无需检测）；
- **阅卷人**：事后核验器（如 饥饿活锁=任务池非空∧全AGV空转持续N步）。

核验器确实是规则，但它是**确诊手段（化验单），不是诊断过程**。不对称性有三：
1. **信息**：核验器读全量轨迹、算全局谓词、事后全知；诊断器只看 ≤8k 压缩档案、事前。
2. **假设来源**：核验器知道该看什么（人把假设喂给它）；诊断器必须自己从档案里产生假设——
   难点不在"判断是不是活锁"（一个谓词），在"从上千可能解释中找对该看哪个统计量"。
3. **可维护性**：每个新失效模式出现，规则诊断器都要人重写（且在重写前它silently给错答案）；
   耦合系统的教训恰是新模式不断涌现（活锁/走廊拥塞在纯FJSP/纯MAPF中不存在）。

**无标签错误的验证**（词表外的病怎么判）——两条路：
1. **反事实判分不需要标签**：干预→同seed重仿真→ΔKPI，直接判"该诊断在操作上是否有效"。
   这是干预桥存在的核心意义：无标签判卷机。（诚实备注：ΔKPI 验证的是干预有效性而非解释
   正确性，故它是三判分之一，不单独定案。）
2. **Unseen 留出实验**：把一种已知病整体从词表抽走（标签在手、词表没有），测模型
   (i) 是否用 unseen 逃生舱承认不认识 (ii) 是否仍给出 ΔKPI 有效的干预。

**可检验主张（窄而诚实）**：① 标签虽由构造为真，但"诊断规则"需按场景逐参数重写，
LLM 跨网格泛化（随机化目标/时刻/参数就是量化这一点）；② 验证-诊断的信息不对称构成真实
难度差，用"规则基线在同档案 hard 档的塌陷"来测量；③ 无标签模式可由反事实桥验证。
若规则基线在同档案 hard 档与 unseen 上仍不塌陷 → 诚实结论"LLM 无优势、规则够用"，
框架+基准仍为贡献（已预注册）。

## 7. 工程件与顺序

①档案构建器升级（证据ID+**粒度阶梯**+预算+**hard 视图三防线质检**）→ ②Prompt v2 → ③LLM 诊断器 → ④评分器 → ⑤反事实执行器 → ⑥agentic 工具层。
前置：场景生成器（第1步网格）+ **hard 视图质检**（三防线，含 cases_v2 回溯复验）；场景生成器 + ①④ 即"出题-判卷"闭环，不依赖 LLM API，可先行。
扩展臂（P2 首个数字之后）：⑦ L4 显著性模型训练（baseline 轨迹无监督）+ L4 档评测 + 神经检测器单臂。
