## 速度与思考链问题（三轮对照）

| 方案 | 生成 tok | 速度 | 解析 | 备注 |
|---|---|---|---|---|
| OpenAI兼容 + /no_think(系统位) | 4.5-5.4k | 34 tok/s，110-160s/案 | ✓ 4/4 | 思考链没关掉 |
| 原生API think:false | 3.1k | 35 tok/s，88s/案 | ✗ | 思考链仍开，输出混叙述 |
| **JSON Schema 约束解码** | 214 | **1.6 tok/s** | ✓ | 格式绝对合法但 Ollama 语法采样开销 20 倍，不可用 |
| /no_think(用户位) | 3.9k | 35 tok/s，110s/案 | ✓ | 思考链仍开 |

**结论：思考链关不掉是延迟主因**（有效答案只 ~150 token，思考烧 3-5k）。
Qwen3-4B 混合思考模型在 Ollama 里无可靠关闭手段。

## 三个已确认的设计决策

1. **本地评测协议 = 提示约束 + 宽解析 + JsonRegen 重试**（34 tok/s 可用）；Schema 约束解码
   留给服务器 vLLM（xgrammar 引导解码无此开销）——这正是"本地调试/服务器正式"的分界。
2. **定位词表改双字段**：schema 约束下模型把占位符 `machine:<id>` 原样抄进输出 →
   改为 `loc_type`(enum) + `loc_target`(如 "machine:0") 两字段，评分时类型/编号分开计。
3. **吞吐估算**：单线程 ~2 分钟/案 → 200 案例约 7 小时；Ollama 并行(OLLAMA_NUM_PARALLEL)
   或换无思考模型（qwen2.5:3b-instruct，待拉）可压到 1-2 小时。正式数字以服务器 vLLM 为准。
