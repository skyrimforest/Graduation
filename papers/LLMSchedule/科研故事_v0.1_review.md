# LLM4Schedule 科研故事完整叙述(v0.1,供外部 review)

> 阅读前置:文中"SkyEngine"指我们已有的 FJSP-MAPF 联合仿真环境(另有论文),"SkyCausal v3"指其前身 solver-portfolio 元调度工作。

## 1. 一句话定位

**LLM4Schedule:让 LLM 作为在线 Coordinator,在 FJSP-MAPF 联合调度中输出三层算子组合(FJSP 算子 × AGV 分配规则 × MAPF 求解器)+ 参数配置,以多层耦合执行反馈为训练信号,通过 SFT + RL 两阶段获得超越任何固定算子组合的调度性能。**

## 2. 问题背景

### 2.1 场景与三层算子堆叠

柔性制造系统的调度由三层算子堆叠:

| 层 | 决策 | 算子池示例 |
|---|---|---|
| FJSP(车间调度) | 工件→机器、工序排序 | 各类 PDR、启发式、精确求解器 |
| Assigner(任务分配) | 搬运任务→AGV | 就近分配、负载均衡、学习式分配 |
| MAPF(多智能体路径) | AGV 无碰撞路径 | CBS 系、优先级规划、规则式路由 |

三层间存在三类耦合损失(距离盲区、时序错位、拥堵聚集):FJSP 只看加工时效会选远端机器,AGV 长距离搬运使总工期反而变长;搬运时序错位造成机器空闲或物料堆积;同区域任务集中引发窄通道拥堵。

### 2.2 核心现象:算子组合无单一最优

**三层算子的最优组合随系统状态漂移**:"多 job 长流程"状态下 A 组合最优,"拥堵聚集"状态下同一组合显著劣化。固定组合必然次优;组合空间是三层笛卡尔积(约百级),逐状态穷举不可行。这是一个经典 algorithm selection / hyper-heuristic 问题,但发生在多层耦合的联合调度场景——此前无人用 LLM 做(文献调研见 §3)。

### 2.3 为什么是 LLM:执行与统筹的分工

LLM 直接输出调度/路径决策已被证明失效(ReflecSched, arXiv:2508.01724 论证了三个失效模式:长上下文悖论——prompt 中 >70% 静态状态被忽略;启发式闲置——指示 LLM 遵循 PDR 也不遵守;短视贪婪——局部好选择造成下游瓶颈)。而**无语义推理的自适应选择**(bandit 类)只能在"试错统计"层面适应,无法从反馈中理解"拥堵聚集该换 MAPF 求解器"这类跨层因果结构。

我们的核心主张:**LLM 的价值不在执行,在基于状态语义与耦合反馈的算子统筹。**

## 3. 相关工作与空白(调研于 2026-08)

术语约定:"在线"= episode 内 in-the-loop(仿真回合进行中介入);"离线"= episode 外(部署前生成)。所有相关工作与本文同为离线仿真实验,"在线"不作为卖点。

| 类别 | 代表工作 | 机制 | 与本文差异 |
|---|---|---|---|
| LLM 直接调度 | ReflecSched (2025) | LLM 分析启发式 rollout 轨迹,蒸馏自然语言经验指导决策 | 单层 DFJSP;输出自然语言(不可验证);我们用它论证"LLM 不做执行器" |
| LLM 选进化算子 | LAOS (GECCO'25), LLM4EO (2025, FJSP) | EA 迭代循环内 LLM 依据适应度增量选 crossover/mutation 等算子 | 被选的是 EA 算子非调度算子;反馈是单目标适应度,不携带调度-搬运耦合信息;LLM4EO 仅 FJSP 单层 |
| LLM 调参 | LLaMEA-HPO (van Stein), Neurocomputing 2026, LLMHHEA | LLM 做算法配置/参数调优 | 启发"结构与参数分离"原则;均非多层调度场景 |
| LLM 生成规则 | Eureka / FunSearch 脉络 | LLM 离线写启发式代码 | 归姊妹篇 LLM4Envolve,不在本文范围 |

**四个空白**:
1. 无人做 FJSP-MAPF 多层耦合场景的 LLM 算子选择;
2. 反馈信号不携带跨层耦合信息(现有均为单层 rollout 假想代价或适应度增量);
3. 现有输出空间偏软(自然语言经验,不可验证、不可复现);
4. LLM × MAPF 交叉基本为空。

## 4. 方法

### 4.1 决策接口

LLM 在**慢时间尺度**(episode 级 / 扰动事件级切换点)介入,输入为结构化状态摘要(防长上下文悖论:只给压缩后的耦合相关特征,不给原始全量状态)+ 历史选择-结果反馈,输出为:

```json
{
  "fjsp_solver": "SPT_rule | critical_path | GA | ...",
  "assigner": "nearest | load_balance | RL_policy | ...",
  "mapf_solver": "CBS | prioritized | rule_based | ...",
  "params": {"lookahead_steps": "coarse_grid_level", "w_congestion": "coarse_grid_level", ...},
  "rationale": "简短理由(用于可解释性,不参与约束)"
}
```

设计要点:**结构(离散组合,合法集合内约束解码)与参数(离散化档位)分离**(借鉴 LLaMEA-HPO);高频决策留给底层算子执行,规避 LLM 延迟;输出全程可验证。

### 4.2 反馈信号:多层耦合执行反馈(核心差异化)

SkyEngine 是闭环共仿真:每个调度动作立即与 AGV/机器状态交互(AGV 真实移动、阻塞、绕行),执行结果重塑机器可用性与后续决策点,并有覆盖 FJSP/MAPF 两侧的 17 项指标。因此 LLM 读到的反馈携带**跨层联动信息**(如"换 MAPF 求解器后拥堵下降、机器空闲上升")——单层选择器在结构上无法获得。这是与 ReflecSched(lookahead 假想轨迹)和 EA 系(适应度增量)的本质区别。

### 4.3 训练方案:SFT + RL 两阶段(+ 蒸馏)

LLM4Schedule 满足 RL 友好的三条件:输出离散可验证、奖励来自仿真 ground truth、决策频率低(采样成本可控)。

**阶段 0 数据引擎**:系统枚举"状态快照 × 组合"跑仿真(约 100 组合/状态),取 Top-k 组合及其指标作为多标签语料;状态快照从多样化 episode 抽取;参数用粗档位标注。SkyCausal v3 的 portfolio 搜索数据可直接转为语料。

**阶段 1 SFT(冷启动)**:学"状态 → Top-k 组合"的格式与基本判断;JSON schema 约束解码保证格式合规。**DAgger 式迭代**:student rollout 诱导的状态补 oracle 标签再训,消除分布偏移(与我们另一篇工作的"student-induced states 蒸馏"哲学同构)。

**阶段 2 RL(GRPO)**:同一状态快照采样 G 个组合,各自跑仿真,组内相对改进量作 advantage。奖励:

```
r = α·(makespan 改进 vs baseline组合) + β·(拥堵指标改进) + γ·(格式合法)
```

要点:(1) 以相对固定 baseline 的改进为基,消解 instance 难度方差;(2) α/β 权重向量作为 prompt 条件(multi-objective conditioning),一个模型按偏好出策略,顺带回应"17 项指标如何权衡";(3) KL 锚定 SFT 策略防格式漂移;(4) 警惕 reward hacking(权重偏拥堵时可能过度保守),需正则。

**阶段 3(可选)蒸馏**:大模型 → 4B/8B 小模型,同时赢性能与延迟/成本。

## 5. 实验设计

### 5.1 Baselines

1. 固定最优单组合(oracle-per-dataset,SkyCausal v3 组合器搜索得到);
2. 随机组合 / 轮转;
3. 无 LLM 自适应选择:Thompson sampling、UCB、EXP4;
4. SkyCausal v3 的非 LLM 元调度器(前身直接对比);
5. Frozen 大模型 + prompt(不训练,ReflecSched 式);
6. 单层 LLM 选择器(只选 FJSP 算子,消融多层性);
7. 自然语言经验输出(消融输出空间可验证性);
8. LLM 直接调度(复现三失效,作为下界参照)。

### 5.2 关键实验:凸显语义推理优势

按三类耦合损失构造**分状态评测集**(距离盲区主导 / 时序错位主导 / 拥堵聚集主导的状态簇),展示 bandit 在状态语义切换处反应慢或错误、LLM 能从反馈推理出切换理由——而非在均匀随机场景比总分。这是"LLM 比 bandit 强在哪"的核心证据。

### 5.3 消融矩阵

只 SFT / 只 RL / SFT+RL / +蒸馏;有/无耦合反馈(把反馈换成单指标 makespan,验证多层反馈的价值);有/无 DAgger 迭代;有/无 rationale 输出。

### 5.4 预期核心结论

1. SFT+RL 小模型(7B 级)> frozen GPT-4o 级大模型(性能 + 延迟双赢);
2. LLM4Schedule > 所有固定组合与 bandit 类,尤其在状态漂移场景;
3. 多层耦合反馈 > 单指标反馈(消融);
4. 输出可验证组合 > 自然语言经验(消融)。

## 6. 与姊妹工作的边界

- **LLM4Schedule(本文)**:在线、组合已有算子——消费专家池;
- **LLM4Envolve(另文)**:离线、进化生成新算子(LLM 写 dispatching rule 代码)——生产专家池;
- 共享 SkyEngine 环境与专家池基建,互相引用,方法与贡献不重叠;
- 与 SkyEngine 论文(环境)/ SkyCausal v3(非 LLM 元调度前身)的关系:环境提供反馈接口,前身的组合器是数据引擎与最强基线。

## 7. 贡献声明(草稿)

1. 首个面向 FJSP-MAPF 多层耦合联合调度的 LLM 算子组合选取框架,输出空间离散可验证;
2. 提出以多层耦合执行反馈为信号的 SFT+RL 训练方案(DAgger 式冷启动 + GRPO 精进 + 多目标条件化);
3. 大规模实验:证明语义推理优于统计自适应(bandit)与固定组合,训练后小模型优于 frozen 大模型。

## 8. 请 reviewer 重点评判的问题

1. 故事主线"组合无单一最优 → 需语义统筹 → LLM 是合适的语义统筹器"是否成立?哪一环最弱?
