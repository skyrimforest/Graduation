# SkyOrch 科研故事 v0.2

> v0.1 → v0.2 变更:吸收外部 LLM review(2026-08-27)的采纳项。原故事的核心缺陷是"state-dependent selection ⇒ LLM"这一步不成立(中间隔着 MLP/GNN contextual selector 一整片方法空间),v0.2 用**开放集编排 / 组合泛化**补上这一箭。v0.1 保留于 `科研故事_v0.1_review.md` 作历史。

---

## 1. 一句话定位

**SkyOrch:让 LLM 作为跨层求解器编排器(solver orchestrator),在 FJSP-MAPF 联合调度中于慢时间尺度选择可执行的三层求解器栈(FJSP 算子 × AGV 分配规则 × MAPF 求解器)+ 语义参数档位;以数字孪生的匹配状态反事实执行反馈为监督信号(SFT 冷启动 + 长序列 RL 精进);其不可替代性在于对 regime shift、objective shift 与专家池演化的组合泛化,而非平稳封闭选择集上的精度。**

命名:原 LLM4Schedule 已被 CityU/HKU 系 2026 SSRN 论文占用(已核实),更名 SkyOrch,延续 SkyEngine/SkyCausal 家族。

## 2. 主线逻辑链(v0.2)

```
跨层耦合(三类耦合损失:距离盲区 / 时序错位 / 拥堵聚集)
  ↓
无支配性求解器栈:三层算子的最优组合随运行 regime 漂移
  ↓
因此联合调度本质上是一个 solver orchestration 问题,而非设计单一 integrated 算法
  ↓
封闭集选择器(MLP/GNN/bandit)足以处理平稳的状态→组合映射        ← 主动承认
  ↓
但真实系统存在 regime shift + objective shift + 专家池演化        ← 核心论证位置
  ↓
需要组合泛化能力 → 语言条件化的 LLM coordinator(能力卡驱动的开放集编排)
  ↓
分工:LLM chooses, verified solvers execute
  ↓
SkyEngine 提供匹配状态的反事实执行监督(counterfactual supervision engine)
  ↓
SFT 学 oracle 行为;RL 学长序列自适应编排(分布校正 + 序列 credit assignment)
```

关键转变:v0.1 卖"LLM 有语义推理所以选得准";v0.2 卖"**LLM 在平稳封闭选择上未必有优势,但在组合泛化上不可替代**"——预期结论形态从"LLM 全都赢"改为"IID 平手、OOD/新专家/新目标 LLM 胜",科学价值更高且风险敞口更小。

## 3. 方法(v0.2 修订)

### 3.1 决策接口:semi-MDP / options 形式化

LLM 在宏观决策点 $T_0, T_1, \dots$(扰动事件触发 / 周期性,两者都做并对比——文献支持 periodic 更 robust)选择求解器栈,底层算子在 $[T_k, T_{k+1})$ 内执行:

$$\pi_\theta(a_F, a_A, a_M, \phi_{\text{sem}} \mid s, h, w, \mathcal{E})$$

- $w$:运营偏好向量(少量真正 operational objective);
- $\mathcal{E}$:**当前可用专家的能力卡集合**(textual capability cards)——这是开放集编排的接口;
- $\phi_{\text{sem}}$:**语义参数档位**(如 congestion sensitivity: low/med/high),不是数值。

工程细节:切换成本 $c_{\text{switch}}(A_{k-1}, A_k)$ + 最短驻留时间(防疯狂切换)。

**参数输出收缩**(采纳 LLaMEA-HPO 教训):LLM 只输出结构 + 语义档位,数值参数交给小 tuner(lookup/BO)。"LLM 选 solver + 十几个数值参数"违背已知经验。

### 3.2 反馈信号:反事实监督引擎(需环境工程前提)

反馈向量四分组:

$$f_t = [f^{\text{proc}}, f^{\text{transport}}, f^{\text{traffic}}, f^{\text{interaction}}]$$

其中 $f^{\text{interaction}}$(机器因运输而饥饿、加工因拥堵而延迟等)才是**跨层耦合的显式证据**——"有 FJSP 指标 + 有 MAPF 指标"不等于 cross-layer feedback。

反事实机制:冻结状态 $S_t$,多组合从相同状态启动、共享随机数 $\xi$,得 $Y(S_t, a_i, \xi)$ 与配对差分 $\Delta_{ij}$——matched-state counterfactual feedback,而非"这次 makespan 是 100"的孤立轨迹反馈。

**⚠️ 工程前提(待确认)**:仿真器需支持状态冻结 + 分支 rollout + 随机数共享。若不可控,降级为多 seed 相对比较,claim 相应降级。

**Oracle 定义必须严谨**(坑):枚举得到的不是泛泛的 ground truth,而是"**指定延续策略与 horizon 下的反事实 rollout oracle**"($Q^{\text{hold}}$ / $Q^\pi$ / $Q^*$ 三者完全不同,论文中必须写明用的是哪种)。若延续策略本身是当前策略,则自然形成 policy iteration 式结构($Q^{\pi_k} \to \pi_{k+1}$),比泛泛说 DAgger 更漂亮。

### 3.3 指标体系:观测与目标彻底拆开

- **硬约束**(必须满足):collision=0, deadlock=0;
- **真正的优化目标**(2–4 个):$J = (C_{\max}, \text{tardiness}, \text{energy})$;
- **其余 13+ 项指标 = 观测/诊断信号**,作为 $s_t / f_t$ 输入,不进 reward——congestion 可能只是 makespan 的 mediator,同时优化反而改变任务目标。

多目标条件化 $\pi(a \mid s, w)$ 保留为 **standard preference interface**(已有 preference-conditioned GRL 先例),不列为主要创新。

### 3.4 训练方案(v0.2 修正)

**阶段 0 数据引擎**:枚举/采样"状态快照 × 组合"反事实 rollout(共随机数),记录 $f^{\text{interaction}}$ 分组反馈;SkyCausal v3 portfolio 数据直接复用。

**阶段 1 SFT(冷启动)**:学"状态 → Top-k 栈"的结构化 JSON 输出;约束解码保证格式。DAgger 式迭代补 student-induced 状态标签。

**阶段 2 RL(GRPO,作用于多切换长轨迹)**:

- **v0.1 错误已修正**:
  - ~~格式合法奖励项~~ 删除(约束解码下恒为 1,无训练信号;非法动作交给 action masking);
  - ~~"RL 超越监督上限"~~ 改为"超越 SFT policy"。RL 不可能超过同定义 exhaustive oracle;其收益来源 = **分布校正**($d^{\pi_\theta} \neq d^{\text{oracle data}}$)+ **序列 credit assignment**(当前切栈改变未来状态分布,单步 Q 回归覆盖不了)。
- **GRPO 必要性论证**(预答 "Why RL?"):若只是单步 s→a 且已枚举全部动作,cost-sensitive classification / Q 回归即够。RL 的存在理由是我们优化的是**episode 级多切换策略**(含切换成本、驻留约束、诱导分布),这是回归类方法不覆盖的目标。
- 奖励:$r = $ 相对固定 baseline 栈的 $J$ 改进 $-$ 切换成本惩罚;$w$ 条件化;KL 锚定 SFT。

**阶段 3(可选)蒸馏**:小模型逼近 frontier frozen LLM,claim 写法降险:"训练使紧凑模型成为有效的领域 coordinator,大幅缩小与更大 frozen 模型的差距同时降低推理成本"——若真赢了再上升为亮点,不进核心贡献。

### 3.5 rationale 降权

输出中的 rationale 保留(可解释性),但**不作为"LLM 在推理"的证据**(post-hoc explanation 风险)。真正的推理证据来自 §4 的受控干预实验。

## 4. 实验设计(v0.2,分两档控制工程量)

### Baseline 四梯队

| 梯队 | 成员 | 回答的问题 |
|---|---|---|
| Static | best fixed / random / oracle-static | 动态选择有没有价值 |
| Statistical | UCB / Thompson / contextual bandit | 统计自适应够不够 |
| **Learned meta-controller** | **RF / MLP / GNN selector、$\hat{Q}(s,a,w)$ 回归 + argmax、DQN/PPO selector(同信息、同数据、同动作空间)** | **最危险的对照,必做** |
| LLM | frozen → SFT → SFT+RL | 本文方法 |

外加:SkyCausal v3 非 LLM 元调度器(前身)、单层 LLM 选择器(消融多层性)、LLM 直接调度(下界参照,复现三失效)。

### Must-have(承载核心 claim,三项)

1. **Unseen-expert generalization(核心中的核心)**:训练时专家池 $\{M_1..M_k\}$,测试时注入 $M_{k+1}$,只给文字能力卡("bounded-suboptimal MAPF solver;强于高冲突密度;成本随 agent 数陡增;支持 warm start"),不重训。看 LLM 能否把新 solver 用在正确状态上。MLP 结构性做不到($a_{k+1} \notin$ 训练输出空间)。Claim 升级为 **open-set orchestration over evolving solver portfolios**。
2. **Controlled regime transition**:构造 $R_1 \to R_2 \to R_3$ 漂移,度量 detection latency / adaptation latency / cumulative regret / switch count / steady-state gap——不只比最终 makespan。
3. **IID vs OOD 对照**:预期并主动呈现"IID 封闭集上 MLP ≈ LLM,OOD/新目标/新专家上 LLM > MLP"。结论:"LLM 对平稳封闭选择不必要,对组合泛化有价值"——比"LLM 全都赢"更可信也更高级。

### Nice-to-have(增强项,可入附录/二期)

4. Objective shift:换 $w$ 语义(交期优先 ↔ 能耗优先)看适应;
5. $\tau_{\text{ctrl}} / \tau_{\text{drift}}$ 时间尺度扫描(0.1–2),找 sweet spot,直接回应适用边界;
6. Factor-specific sensitivity:只增 conflict density、保持加工负载,看模型是否系统性只动 MAPF 层(受控干预证据,替代 rationale 作为推理证据);
7. 切换成本/驻留时间消融;DT+LRM+bandit(JMS 2026)正面对比。

## 5. 贡献声明(v0.2,三层抽象)

1. **Problem formulation**:将 FJSP–transport–MAPF 联合控制形式化为**多时间尺度跨层求解器编排问题**——高层 coordinator 选择可执行求解器栈,而非直接生成低层调度;
2. **Counterfactual learning mechanism**:构建**数字孪生反事实监督回路**——从匹配冻结状态评估候选求解器栈、暴露跨层执行后果(含 interaction 指标),支持 oracle 蒸馏 + 序列策略优化;
3. **Generalizable coordinator**:发展**约束化组合 LLM coordinator**,支持状态/目标/专家条件化编排,并系统评测 regime shift 与 unseen expert portfolio 下的适应能力(而非仅 IID 性能)。

## 6. 与姊妹工作的边界(v0.2 重钉)

- **SkyOrch(本文)**:在线、组合已有专家——**读卡组合**(读取专家能力卡做组合推理);
- **LLM4Envolve(另文)**:离线、进化生成新算子——**写卡生产**(LLM 写 dispatching rule 代码,生成的新专家带卡入池);
- 概念交叠处的钉法:开放集编排(SkyOrch)消费的是"已有但未见"的专家;规则进化(LLM4Envolve)生产"原本不存在"的专家。前者验证语言条件化组合推理,后者验证代码空间搜索,实验协议与贡献不重叠。
- 与 SkyEngine 论文:环境提供反事实监督接口(引用);与 SkyCausal v3:其 portfolio 组合器是数据引擎 + 最强 learned 基线(前身直接对比)。

## 7. 遗留风险与 fallback

| 风险 | 应对 |
|---|---|
| 仿真器不支持状态冻结/随机数共享 | 降级为多 seed 相对比较,反事实 claim 降级为"配对评测" |
| Unseen-expert 实验失败(LLM 不会用新卡) | 故事回退到 v0.1 主线(regime shift + 分状态语义优势),但需补强 neural selector 对比;这是最大的单点风险,**建议最先做这个实验的 pilot** |
| MLP 在 OOD 上也不差 | 检查 OOD 构造强度;若确实如此,诚实呈现边界,论文重心移向反事实监督机制(贡献 2) |
| 引用真实性 | 外部 review 的引文(ChatGPT 检索产物)写入 related work 前逐条核实原文;撞名已核实为真 |
