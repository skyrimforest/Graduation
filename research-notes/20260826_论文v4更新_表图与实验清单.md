## 1. 旧搜索代码的复用结论（回答"面向元搜索的算法能不能用于新场景"）

**结论：直接复用，因为新主角本来就是元级。** Phase 7 的搜索栈
（`budgeted_search/`）从头到尾就生长在 (状态, 算子组合动作) 接口上——
`mcts_node.py`、`uniform_search.py`、`random_search.py`、`rollout_policy.py`、
`transition_backend.py`、`budget.py` 搜的都是"用哪个组合"，与今晚定稿的
组合空间搜索**是同一个空间**。被证伪的从来不是这些机器，而是外层的
策略形态（周期触发 + 固定菜单 + 树分配预算）。因此：

| 部件 | 复用方式 | 改动量 |
|---|---|---|
| transition_backend / budget / rollout_policy | 原样复用 | 0 |
| racing.py（+测试） | 作为评估内核原样复用 | 0 |
| mcts_node.py | 复用树结构，改用途：周期深控 → 决策点 anytime（触发、深度剖面、评估内核换 racing） | 小 |
| uniform_search / random_search | 直接成为强制基线（及格线）与 golden trace 采样器 | 0 |
| sequential_admission / orchestration_action | V0 候选池与合法性掩码来源 | 0 |
| trigger_policy（迟滞/冷却，有测试） | 切换层防抖直接接线 | 0 |
| V1 组合文法候选生成器 | **唯一真正的新代码**：按维度合成候选 + 参数档 | 小（配方空间本就按维度结构化） |
