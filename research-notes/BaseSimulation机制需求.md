# BaseSimulation 机制需求清单（由 LLM4Schedule 与 LLM4Evolve 反向推导）

> 记录时间：2026-08-26 ｜ 性质：工程需求清单（非调研）
> 推导来源：`LLM4Schedule/README.md`（LLM 联合整体调度定案）+ `LLM4Schedule/观察语言与训练流水线.md`（观察语言/训练四阶段）+ `LLM4Evolve/README.md`（算子级进化与双层优化定案）
> 用法：BaseSimulation 是两条研究线的共同地基。按优先级分层：**P0 未齐则两条线都动不了**；P1a/P1b 分别服务各自研究线，可并行；P2 为增强项。

## P0：两条线共同依赖的地基

| # | 机制 | 服务 | 说明与验收标准 |
|---|---|---|---|
| 1 | 决策事件钩子 | 两线 | 在机器空闲 / 工件到达 / 插单 / 异常 / AGV 空闲等决策事件处可注册回调；事件流可枚举、可重放 |
| 2 | 状态快照序列化 | 两线 | 决策时刻导出结构化快照（工件/机器/AGV/队列/拥堵统计）；字段定序确定、格式带版本号 |
| 3 | 合法动作集查询 | Schedule | 给定状态枚举可行 (工序, 机器) 与 (任务, AGV) 组合——动作掩码、schema 受限解码、校验的统一依据 |
| 4 | 轨迹记录器 | 两线 | 每决策事件落盘 (快照, 合法动作, 实际动作, 后果)；同一格式同时充当 SFT 数据、DAgger 样本源、进化评估记录 |
| 5 | 种子确定性 | 两线 | (实例, 事件流, 种子) 完全决定一次 rollout——缓存评估与公平对比的前提；需做一次专门的确定性审计（同输入重跑逐位一致） |
| 6 | 实验归档 | 两线 | run 目录约定：config hash / git commit / 指标 JSON / 轨迹文件 / 渲染图；结果可复现、可直接喂反思与诊断 |

## P1a：LLM4Schedule 专属

| # | 机制 | 说明与验收标准 |
|---|---|---|
| 7 | 专家 oracle 任意状态重规划 | DAgger 前提：从任意中间状态对剩余问题重跑专家管线、取该状态的专家动作；依赖状态保存/恢复；支持多专家配置切换（不同 PDR 混合、随机平局打破），避免克隆单一偏见 |
| 8 | 观察语言特征层 | 六类特征 × 两时态（见《观察语言与训练流水线》§1），挂 MetricsHub 扩展；前瞻特征需要 AGV 目的地登记表 + 即将完工工序预测；输出即"状态快照文本"的生成器 |
| 9 | 动作校验与 PDR 兜底 | LLM JSON 输出的 schema 校验 + 可行性校验 + 失败回退路径（纯推理期护栏，不进训练） |
| 10 | 自然语言事件注入 | 动态事件带意图元数据（例："特急单 J7 优先级 200，其他让路"），供语言条件化对比实验——LLM 独有能力的实验接口 |

## P1b：LLM4Evolve 专属

| # | 机制 | 说明与验收标准 |
|---|---|---|
| 11 | 算子接口契约 | 固定 obs 进/出签名（对齐 Coordinator 的 observation 结构），版本化管理；LLM 产出算子可插拔、可沙箱、可组合 |
| 12 | 沙箱执行 | LLM 生成代码在隔离子进程运行，超时/崩溃 = 最差适应度；资源限额（CPU/内存/时间） |
| 13 | 批量评估 harness | 并行多种子 rollout；缓存（同代码 + 同场景不重评）；评估吞吐直接决定进化预算 |
| 14 | 场景族生成器 | 实例 + 事件流参数化（插单率 × 异常率 × 特急单比例网格），种子固定可复现；held-out 场景族第一天锁箱，防进化过拟合 |
| 15 | 瓶颈诊断报告 | 析取图关键路径、机器空闲间隙统计、AGV 饥饿时长、队列时序、插单扰动半径 → 固定格式的"瓶颈报告"，喂反思循环（不是让 LLM 看原始指标自由发挥） |

## P2：增强项（不阻塞主线）

| # | 机制 | 服务 | 说明 |
|---|---|---|---|
| 16 | 甘特图 / AGV 轨迹 / 热力图渲染 | Evolve（VLM 视觉反思）、两线调试 | 从轨迹离线渲染即可，不需要在线 |
| 17 | 执行速度优化 | Evolve（也利 Schedule 数据生产） | 进化评估预算受限于 rollout 吞吐，热点路径提速的收益直接且线性 |

关键内部依赖：
