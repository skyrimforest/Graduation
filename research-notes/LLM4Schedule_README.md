> 内容：三个问题的落地方案——状态怎么表示（观察语言）、为什么联合层适合 LLM、怎么训练。

## 1. 运行时状态体系 = 给 LLM 设计"观察语言"

不是单一"拥堵值"，而是**一组正交的状态摘要机制**，每个机制捕捉一种运行时现象。按六类组织，每类都有现在时/将来时两种时态：

| 类别 | 现在时特征 | 将来时（前瞻）特征 |
|---|---|---|
| **时空热度** | 区域占用率、AGV 密度/区域容量比、热点区 top-K（含趋势↑↓） | 由 AGV 当前目的地推算的"即将到达"流量分布 |
| **流量冲突** | 对向相遇率、交叉点冲突频率、等待步数占比 | 预测绕行率（规划路径 vs 畅通路径） |
| **任务-资源耦合**（命脉） | 待搬运任务队列与等待时长、空闲 AGV 位置、供需比 | 即将完工 next-K 工序 → 未来搬运需求预测、各机器到最近空闲 AGV 的 ETA |
| **机器侧** | 队列长度、负载率、空闲间隙 | 瓶颈指数（关键路径贡献占比） |
| **工件侧** | 就绪工序集、剩余加工量、交期裕度 | 拖期风险分级 |
| **全局事件** | 仿真时刻、完成度、WIP 水平 | 近期事件摘要（插单/故障/特急单） |

要点：
- **任务-资源耦合类是联合层的命脉**——FJSP 与物流的接口面，联合决策的价值全在这里兑现。
- **前瞻特征必须有**：调度决策作用于未来。只给当前占用 = 事后避堵；给"即将到达流量 + 未来搬运需求" = 提前避堵。这也是人类调度员看板的读法。
- 原始数据（AGV 轨迹、队列时序）环境里都有，计算挂在 MetricsHub 扩展上（见机制需求 #8）。

### 五条设计原则

1. **聚合粒度对齐决策**：区域/通道级统计，不做格子级——LLM 消费实体与关系，消费不了场（field）。
2. **派生量优先于原始量**：交期裕度好于"交期−当前时刻"两个原始数，排名好于绝对值。**把算术放进特征工程，把权衡留给模型**——这是文本 LLM 数值短板的主要补救。
3. **决策相关性**：每个特征都要能回答"它凭什么改变 (工序, 机器, AGV) 的选择"；不相关的特征浪费上下文还引噪声。
4. **归一化 + 离散分级**：数字按实例尺度归一；拥堵类特征给 low/med/high 分级，比小数点抗噪。
5. **特征充分性可检验**：训练前用简单分类器（如 GBDT）从特征预测专家动作——准确率高说明特征信息够；低则先补特征再上 LLM，别急着训练。

## 2. 为什么联合层适合 LLM（四论点，深化 README §11）

1. **信息结构匹配**：联合层状态是"实体 + 关系 + 中等数量数值"，正是自然语言最擅长序列化的结构——人类调度看板就是文字和表格。对比：MAPF 低层是稠密空间场（网格），纯 FJSP 排时是稠密算术，语言在两种表示下都是糟糕介质。
2. **决策结构匹配**：联合决策的本质是带定性权衡的组合选择（"这道工序急，但它的机器离所有 AGV 都远"），是权衡判断（LLM 强项）而非精确数值优化（弱项）；路径微操与时刻精调恰好相反。
3. **误差容忍度匹配**：联合层一个次优决策有界且可恢复（下个事件即纠偏）；MAPF 微操错 = 碰撞、时刻错 = 级联。事件驱动节奏让每次生成都短，复合误差最小。**LLM 的错误画像（数值不精、偶尔非法输出）只有在联合层是"可掩码、可容忍"的。**
4. **语言接口价值只在此层**：插单/特急/故障以语言意图到达，直接调制联合决策，无法进入低层——这是专用策略网没有、也最难进对比实验的能力。

**诚实反例**：纯静态优化意义上，LLM 联合调度器不会超过精心设计的联合求解器。主张是"一个 LLM 逼近整套分解专家管线，同时获得语言条件化和免重工程的泛化能力"——对比实验按此主张设计。

## 3. 训练流水线：四阶段

### Stage 0：轨迹采集（数据契约）

- 专家算子栈在仿真环境里跑场景分布（实例生成器 + 动态事件流 + 种子），在每个**决策事件**处记录 (状态快照文本， 合法动作集， 专家动作， 后果)。
- 采样单位是**事件**而非 episode：数据量 = episode 数 × 每集事件数（万级 episode × 约 300 事件 ≈ 百万级样本），LoRA 足够。
- 专家要**多样化**：不同 PDR 组合、PSO 重规划、随机平局打破——只克隆单一配置会把它的偏见学死。
- 动作 JSON 定死唯一规范形式（字段顺序、ID 格式），否则模型学出漂移格式。

### Stage 1：SFT（行为克隆）

- 状态快照 + 动作 JSON，只对动作部分算 loss；推理用 schema 受限解码。
- 课程顺序：静态小实例 → 动态事件 → 大实例。

### Stage 2：DAgger（纠偏，最关键的一步）

- 行为克隆只在专家轨迹的状态上有标签，模型自己跑偏后的状态没人教。
- 做法：当前模型在环境 rollout，在每个决策点让专家管线对剩余问题重规划取"专家会怎么做"，与模型动作不一致的样本回填训练集，迭代 2–3 轮。
- 前提：专家 oracle 可从任意中间状态重规划（机制需求 #7）——现有重规划机制天然就是 DAgger oracle，这是现有系统给训练送的最大便利。

### Stage 3：超越 teacher（先易后难）

- **3a 专家迭代 / 拒绝采样微调**（STaR 式）：每个状态采 N 个候选动作，环境里试，保留导致好结局的动作做新一轮 SFT。简单稳定，先拿免费红利。
- **3b GRPO/PPO**：reward = −makespan − 拖期 − AGV 空驶惩罚 + 可行性惩罚；KL 锚住 SFT 策略防语言能力塌缩；LoRA 上做，复用 `trainer/` 的 GRPO 代码。RL 放最后：LLM 上 RL 调参代价高，前两阶段能拿的先拿完。

### 贯穿的风险与对策

| 风险 | 对策 |
|---|---|
| 数值精度（Starjob 因素①） | 派生特征 + 归一化（原则 2） |
| 长序列复合误差（因素②） | 事件驱动短生成；快照分块定序；只保留最近 K 步决策历史 |
| 输出非法 | schema 受限解码 + 可行性校验 + PDR 兜底（纯推理期护栏，不进训练） |
| 评估口径 | 按 README §9；核心对比：LLM 联合 vs 分解专家管线（联合性价值）、vs teacher（蒸馏保真度）、语言注入动态实验（LLM 独有能力） |
