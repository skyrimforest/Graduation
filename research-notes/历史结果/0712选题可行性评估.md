# SkyEngine 选题可行性评估与科研主线确认

**日期：2026-07-12**  
**评估对象：** `SkyEngine-0602stable/SkyEngine-0602stable`  
**评估立场：** 按论文立项/严格审稿标准评估代码证据、实验有效性与选题新颖性，不以已有实现规模替代科研结论。

## 1. 结论先行

### 1.1 是否应该换题？

**暂不建议换题。** 当前题目有明确的问题价值，且稳定版本已经具备与之匹配的系统基础：FJSP、MAPF、AGV 分配、事件环境、特征/指标、训练器、算法服务调用、组合测试和初步实验结果均已存在。

但不能确认原始的“大而全版本”已经合理：

> “SkyEngine 统一环境 + 多专家在线蒸馏 + GRPO + 多塔网络”

这不是一个已经被证据支持的单一贡献，而是四个待验证模块的集合。论文应先以**闭环 FJSP–MAPF 环境与学习型 Assigner 的有效性**为主线；多专家、蒸馏与 GRPO 只能在经过严格对照后保留为第二层贡献。

### 1.2 建议的论文定位

中文：

> **SkyEngine：面向 FJSP–MAPF 联合调度的闭环仿真环境与学习型 AGV 任务分配方法**

英文：

> **SkyEngine: A Closed-Loop Co-Simulation Environment and Learning-Based AGV Task Assignment for FJSP–MAPF Joint Scheduling**

它回答的不是泛泛的“RL 能否解决 FJSP”，而是：

> 当调度决策产生的运输任务在真实多 AGV 路网中执行时，路径等待、冲突与阻塞会如何反向影响工序释放和机器利用率？在这种闭环状态下，学习型 Assigner 是否能稳定优于固定 AGV 分配规则？

## 2. 已有代码证据：为什么题目值得继续

稳定版本并非代码骨架，已包含以下可以支撑科研的资产：

| 研究环节 | 已有实现/资产 | 当前价值 |
|---|---|---|
| 闭环环境 | `GridFactoryEnv`、AGV/机器/工件/工序状态、Coordinator、Pogema 网格环境 | 可以承载事件驱动的 FJSP–AGV–MAPF 交互 |
| 求解器解耦 | Job/Route Solver 组件、HTTP 求解器、Docker Compose | 可以比较 FJSP 与 MAPF 算法组合 |
| 状态与指标 | FeatureExtractor、MetricsHub、coupling/reward collectors、diff emitter | 可以构造 Assigner 输入并诊断耦合损失 |
| 学习方法 | PPO、DQN、REINFORCE、GRPO、Distiller、MoE-PPO/MoE-GRPO | 可作为方法探索和消融来源 |
| 实验资产 | benchmark、预实验、系统/生命周期/指标/特征/奖励测试、CSV 结果 | 具备形成可复现实验协议的基础 |

这使项目具备两个较强的天然优势：

1. 不是只在抽象 FJSP benchmark 上训练一个网络，而是有路网、AGV 和路径执行层；
2. 不是只对比一个算法，而是已经具备 FJSP × MAPF × Assigner 的可插拔组合结构。

## 3. 当前不能宣称的内容

以下结论目前**证据不足，不能写进摘要或贡献列表**：

1. “SkyEngine 已完整、稳定地实现 FJSP–MAPF 闭环。”
2. “学习型 Assigner 优于基线。”
3. “多专家在线蒸馏/GRPO 有稳定增益。”
4. “结果在多算法组合、规模和地图上泛化。”

原因是已经发现直接影响证据质量的问题：

- 生命周期测试在项目声明的环境中失败：`run.py` 固定查找 `dataset/fjsp`，而当前包内实际目录为 `dataset/fjsp-instances`；
- `experiment/data/results/experiment_results/results.csv` 的 24 条记录中有 5 条 `makespan=0`；
- 若干结果还出现 `machine_utilization_avg=0`；
- 数据采集相关代码存在明确的 mock、dummy 和 fallback 路径；
- 当前无法据此区分“真实闭环结果”“未完成 episode”“指标未采集”与“开发占位数据”。

这属于**构念效度和测量效度风险**：若 makespan 或利用率不能可靠表示一次完整 episode，任何算法优劣结论都不成立。

## 4. 创新点应怎样收敛

### 创新点一：闭环耦合环境（保留）

不是简单宣称“第一个 Gym 环境”，而应证实以下反馈链真实存在：

`FJSP 决策 → 运输任务 → AGV 分配 → MAPF 执行 → 等待/冲突/绕行 → 到达时间变化 → 工序释放与机器状态变化`

必须用静态运输时间、单向执行和双向反馈三种设置证明这一链条改变结果。

### 创新点二：学习型 Assigner（保留，但先做单模型）

先只证明一个可行动作受 mask 约束的 Assigner，能够在相同 FJSP/MAPF 条件下优于：最近 AGV、最早可用 AGV、最短预计完成时间、负载均衡等规则。

这是论文最应优先拿到的算法结论。

### 创新点三：多专家/蒸馏/GRPO（降级为条件性扩展）

只有同时满足下列条件才保留：

1. 多个专家在**同一个 Assigner 动作空间**内输出可比较的任务–AGV 分配评分；
2. 每位专家在不同拥堵、距离、队列负载状态下确有可复现的性能互补；
3. 固定权重、最佳单专家、行为克隆、PPO 等基线均已完成；
4. 多专家方法在组合外测试中有统计稳定的增益，而不是训练集的最高分。

若其中任一条件不满足，论文只写前两项贡献；这不是失败，反而能避免把不成立的方法写成核心创新。

## 5. 论文必须回答的可证伪问题

| 问题 | 最小对照 | 可接受证据 |
|---|---|---|
| 路径反馈真的重要吗？ | 静态时间 vs 单向路径执行 vs 双向反馈 | 高拥堵/窄通道下 makespan、机器饥饿、AGV 等待出现一致差异 |
| Assigner 真有用吗？ | 最近 AGV、最早可用、最短预计完成、负载均衡 | 相同求解器、实例、seed、计算预算下的均值/置信区间优势 |
| 方法只记住实例吗？ | 按实例/地图/AGV 数/算法组合留出测试 | 未见条件下仍优于规则，或清楚报告失效边界 |
| 多专家真的有用吗？ | 最佳单专家、固定均值、固定验证权重 | 在互补状态和留出组合上稳定改善，不提高不可行率 |

主指标应为 makespan；次指标为总 AGV 等待、机器饥饿时间、冲突/重规划次数、可行率、推理/求解时间。所有 episode 未完成、指标缺失或回退到 mock 的情况必须单独计为失败，不能从均值中删除。

## 6. 近期执行顺序：先验证，不先扩展

### Gate 0：修复并冻结数据契约（必须先完成）

- 统一 `dataset/fjsp` 与 `dataset/fjsp-instances` 的路径与实例格式；
- 让 `test/env_test/test_lifecycle.py` 无需手工改环境变量即可启动；
- 明确 FJSP 与 MAPF 实例的版本、解析入口和单位；
- 增加启动前检查：目录不存在、实例不存在、格式不匹配时应立即报出可读错误。

**通过标准：** 生命周期测试可开始并完成一个固定 seed episode。

### Gate 1：验证环境与指标

- 跑生命周期、特征、指标、奖励四类测试；
- 为每 episode 加入 `completed`、`valid_metrics`、`used_mock`、`fallback_solver` 字段；
- 断言完成 episode 的 makespan > 0，且至少一个机器利用率在合理范围内；
- 手工回放 1 个小实例，核对事件时间线与指标计算。

**通过标准：** 无零 makespan/零利用率假阳性；每个核心指标可由原始事件日志复算。

### Gate 2：闭环价值基线

- 固定一个 FJSP solver、一个 MAPF solver、一个小/中实例集；
- 比较静态时间、单向路径执行和双向反馈；
- 每设置至少 5 个 seed，分低/中/高拥堵；
- 不训练神经网络。

**通过标准：** 能用可信数据回答“路径反馈何时重要”。

### Gate 3：单 Assigner

- 完成四个规则基线；
- 训练一个带动作 mask 的单模型 Assigner；
- 严格按实例/地图留出，并保留失败 episode；
- 报告均值、标准差、95% CI 和相对差值。

**通过标准：** 单模型在至少一个预先定义的留出维度稳定优于最佳规则，或明确其适用边界。

### Gate 4：多专家扩展（可选）

仅当 Gate 3 成功后，运行 MoE-PPO/MoE-GRPO 消融；否则不占用主线时间。

## 7. 最终判断

**选题本身：合理，值得继续。** 你已有的系统资产使它比从头做一个 FJSP-RL 选题更具可行性。

**当前论文结论：尚未成立。** 问题不在于选题错误，而在于运行链路和测量链路尚未被验证；目前最重要的科研工作是建立有效证据，而不是增加新的模型名称。

**推荐策略：** 先把“闭环环境 + 规则/单模型 Assigner”的结果做实；多专家蒸馏和 GRPO 是加分项，不应成为论文能否完成的前提。
