# G1 静态 FJSP-MAPF 耦合价值预验证报告

> 日期：2026-08-02  
> 证据状态：B0/B1 `SUPPORTED`，B3 `PLANNED`  
> Gate 1：`NOT_PASSED`  
> 论文边界：不得据此宣称 causal、OPD、RL 或 route-feedback repair 已有效。
> SkyEngine commit：`f17c55f`  
> SkyEngine-MAPF commit：`5966dcc`

## 1. 研究问题

在执行真实无冲突运输时，将静态网格运输成本加入 FJSP 初始机器选择，是否会：

1. 改变 machine assignment、operation order 和 AGV assignment；
2. 减少不必要的跨机器运输；
3. 改善 terminal production makespan。

本报告只比较：

- B0：生产层忽略运输成本，执行层使用显式 MAPF；
- B1：生产层使用 machine-to-machine BFS 成本，执行层使用同一 MAPF。

两组都不做在线 repair，因此不能回答“已执行路径反馈是否有额外价值”。

## 2. Gate 0 语义修复

旧执行器把 AGV 从 assignment position 直接送到 destination，未访问 task.source。
旧 one-leg 结果只能用于 MAPF adapter 筛选，不能用于联合生产结论。

本轮改造后：

1. 每个任务先执行 empty travel 到 source；
2. 记录 pickup_time 和实际 pickup_at；
3. 再执行 loaded travel 到 destination；
4. empty 与 loaded 时间分别统计；
5. 第一工序从固定 raw-material depot 取料；
6. depot、AGV starts 和 machines 位于同一最大自由连通分量；
7. 保存 machine、operation-order 和 AGV assignment audit。

正式矩阵中 invalid source pickup 和 timestamp-order violation 均为 0。

同一 B1/LG-LaCAM map/seed/config 顺序重跑两次，排除 wall-clock/native
runtime 后完整 episode 记录一致；两次均 makespan 263、92 次 planning、
path SOC total 2756。

## 4. 基础设施纠正策略

初始 J10 四路并发运行中有 3 个 episode 因宿主负载出现 `/plan`
ConnectTimeout。其 `mapf_failure_count=0`，不属于 solver failure。

处理方式：

1. 原始并发结果保留；
2. 只对这 3 个 `(condition, map, seed)` 顺序重跑；
3. solver、budget、cap、代码、地图和 seed 不变；
4. formal aggregate 只替换对应 episode；
5. replacement source 写入 `correction_manifest.json`。

纠正后 B0/B1 各 54/54 完成。

## 6. 决策与机制诊断

Combined 结果：

- machine assignment changes：3,278 / 4,500，72.84%；
- operation order changed cases：63 / 63；
- AGV assignment changes：2,955 / 4,500，65.67%；
- mean inter-machine tasks：62.14 降至 27.25；
- paired mean reduction：34.89 tasks。

当前最直接的机制解释是：B1 倾向于复用同一机器或选择更近的后继机器，从而减少
loaded transport legs。该解释与 makespan 改善方向一致，但尚未证明减少的运输
落在 realized production critical path，也未完成 starvation mediation。

## 7. 负结果与错误证据

### 7.1 one-leg 反向结果

旧 one-leg smoke 中，BFS-aware makespan 283，高于 zero-transfer 的 227。
该结果暴露了执行语义不一致，已明确降级为无效生产证据。

### 7.2 EECBS 动态失败

一个 B0 两段运输状态中，EECBS + Space-Time A* 在 5 秒内仍无解；
LG-LaCAM 约 2.3 ms、LaCAM3 约 15.3 ms 得到合法路径。该状态可行，
失败属于 EECBS 搜索/实现边界。

### 7.3 Idle clearance oscillation

pre-fix client 把 idle AGV 当前格加入 goal signature。idle clearance 每移动一步
都会触发重规划，导致两状态往返：

- pre-fix：98% operation completion，699 plans，达到 1,000 cap；
- post-fix：100% completion，makespan 430，111 plans。

修复后 signature 只包含 active task goals。

### 7.4 Random-map disconnected placement

旧 generator 可把 starts、depots 和 machines 放入不同自由分量，导致 LG-LaCAM
正确返回 process error。现统一从 raw map 最大自由连通分量确定性采样。

## 8. 证据结论

当前可支持：

> 在本项目的两个规模、maze/random 两类拓扑和 4-AGV 设置下，将静态 BFS
> 运输成本纳入初始 FJSP 机器选择，会显著改变生产决策并降低真实两段运输下的
> terminal makespan。

当前不可支持：

- executed route feedback 优于 static BFS；
- congestion predictor 或 causal estimator 带来额外收益；
- learned query gate 在线优于阈值；
- OPD、CBQ-IQL 或其他 RL 算法有效；
- 结果可跨独立 FJSP benchmark family、8 AGV 或动态扰动泛化。

因此 Gate 状态为：

- static coupling sub-gate：`SUPPORTED`；
- route-feedback Gate 1：`NOT_PASSED`。
