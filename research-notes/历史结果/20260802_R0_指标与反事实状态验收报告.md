# R0 指标与反事实状态验收报告

**日期：2026-08-02**

## 1. 结论

R0 状态：`PASSED_FOR_R1`

本阶段完成了工业指标、计划稳定性审计、完整状态分叉、共同外生随机数和运行
manifest。相同 branch state、相同策略和相同 exogenous seed 下，四组
no-intervention twin rollout 的动作、事件、终端状态和完整轨迹哈希严格一致。

该结果只证明反事实实验基础可靠，不证明恢复策略有效。

## 2. 新增指标

交付：

- total/mean/max tardiness；
- total weighted tardiness；
- on-time delivery rate；
- throughput。

恢复：

- machine/AGV availability；
- resource time-to-recover；
- machine/AGV/obstacle outage steps；
- resource disruption loss area；
- paired cumulative performance loss 和 performance time-to-recover。

计划稳定性：

- changed operations；
- machine assignment changes；
- operation predecessor/sequence changes；
- total/max planned start-time shift；
- schedule revision count。

当前 FJSP JSON 不含 due date，因此当前运行的 `due_job_count=0`。零 tardiness
不能解释为没有延期；R1 前必须预注册 due-date 生成规则。

## 3. Snapshot 边界

`skycausal.counterfactual-state.v1` 覆盖：

- jobs、operations、machines、AGVs、transfers；
- 动态障碍、occupancy grid、positions/goals；
- Python、NumPy 和 Pogema 内部 RNG；
- exception schedule/cursor/history/RNG；
- processing-time RNG；
- MetricsHub history/heatmaps；
- JobSolver、Assigner、RouteSolver；
- rolling MAPF 的远端初始化 payload、消费帧和动作前缀。

远端 MAPF 不使用虚假的 Python deepcopy。恢复时重新初始化同一轨迹、seek 到
保存帧并校验动作前缀。

LG-LaCAM 组在 branch point 存在非空远端 trajectory cache，验证覆盖了真实

- action hash 一致；

- outage area 与 event-log 重算结果一致。

## 5. 发现并修复的问题

1. 旧快照只恢复 agent 坐标，没有恢复 Pogema occupancy grid；
2. action sampler、grid 和 per-agent RNG 未保存；
3. 动态障碍、异常游标和加工时长 RNG 未保存；
4. machine/AGV 指标跨 reset 泄漏；
5. MetricsHub 未正确识别 job terminal；
6. rolling MAPF 的远端 cache 不可由本地对象复制；
7. 正式输出缺少 schema、镜像、commit 和文件哈希。
