# 多源扰动与分层恢复验收报告

**日期：2026-08-02**

术语更新：后续统一使用“恢复等级 0-4”。本报告为已冻结的历史证据，保留
`U0-U3` 以对应原始 JSON、图表和 manifest。

## 1. 结论

扰动级联验证状态：未通过

本阶段证明了 machine breakdown、AGV breakdown 和 temporary road blockage
都能沿运输/加工延迟、机器饥饿和实际关键链传播到 terminal makespan。

但当前恢复等级 0-3 的嵌套动作不满足“恢复范围越大、终端结果越好”的假设：

- 恢复等级 1 的主动路径修复对道路封锁有稳定小收益；
- 恢复等级 2 的物料交接平均劣于路径修复；
- 恢复等级 3 的机器迁移平均显著劣于运输重分配。

因此不能进入恢复策略价值验证、因果估计、BNN 或强化学习。下一步必须先重新
设计有选择的运输重分配和局部排程修复动作。

## 2. 实验设计

FJSP family：

- Brandimarte `mk01`；
- Fattahi `mfjs01`。

Topology：

- medium maze；
- validation random。

正式 screening：

- layout/exogenous seeds：0–4；
- severity：low、medium、high；
- recovery：恢复等级 0、1、2、3；
- route baseline：进程内 reservation A*。

补充复核：

- Brandimarte/random/high + LG-LaCAM；
- Fattahi/random/high + LG-LaCAM。

交期固定为 `ceil(1.10 * clean completion time)`。每个动作分支从同一完整快照
恢复，使用相同外生随机数。

## 4. 级联证据

可审计级联 episode 数：

| 扰动 | Episode |
|---|---:|
| machine breakdown | 153 |
| AGV breakdown | 102 |
| temporary road blockage | 79 |

`auditable_cascade` 要求同时满足：

1. 事件实际注入；
2. 受影响 operation/transfer identity 可追溯；
3. 下游工序发生 material/finish delay 或 processing interruption；
4. 延迟进入实际关键路径；
5. makespan 或 TWT 相对 no-event twin 变差。

因此本阶段支持“存在跨生产-物流级联”，但不把该受控实验写成真实工厂的已识别
因果效应。

## 5. 恢复动作结果

正值表示更高层动作改善 makespan。

| 对比 | Paired N | Mean | Bootstrap 95% CI | W/T/L |
|---|---:|---:|---:|---:|
| 道路：等级 1 - 等级 0 | 44 | +0.43 | [0.30, 0.57] | 19/25/0 |
| AGV：等级 2 - 等级 1 | 44 | -1.59 | [-3.05, -0.50] | 0/26/18 |
| 机器：等级 3 - 等级 2 | 53 | -8.89 | [-14.21, -4.08] | 7/23/23 |

LG-LaCAM 两组复核的平均方向：

- 道路路径修复相对不追加恢复：`+0.5`；
- AGV 运输重分配相对路径修复：`-2.5`；
- 机器局部排程修复相对运输重分配：`-21.5`。

说明负结果并非 reservation A* 单一 baseline 造成。

## 6. 解释

运输重分配的问题：

- 即使另一台空闲 AGV 到交接点的 BFS 距离小于维修时间，交接仍会引入空载取料、
  新的路径冲突和分配等待；
- 当前简单成本门槛没有估计这些系统级外部性。

局部排程修复的问题：

- 单工序的“替代机运输 + restart processing”可能小于原机等待；
- 但迁移会改变目标机器队列和后续 transport pattern；
- 局部成本改善不等于 terminal critical-path 改善。

这构成了有价值的反证：恢复动作存在非单调、状态依赖的副作用，但当前动作
proposal 尚不够强，不能直接据此训练 policy。

## 7. Gate 判定

通过项：

- 三类扰动均有可审计级联；
- 两个 family、两个 topology 上存在正 terminal loss；
- 道路路径修复相对不追加恢复的 CI 下界大于 0；
- LG-LaCAM 方向复核完成。

未通过项：

- 运输重分配和局部排程修复的 paired CI 为负；
- 3 个 solver failure；
- 3 个 target-coverage failure；
- LG-LaCAM 不支持这两类扩大恢复动作的正收益。

最终状态：`NOT_PASSED`。

## 9. 下一步边界

继续扰动级联验证，而不是进入恢复策略价值验证：

1. 运输重分配加入 AGV availability、remaining route、handoff queue 和拥堵估计；
2. 局部排程修复只迁移一个候选 operation，显式估计替代机 queue externality；
3. 增加“跳过运输重分配”“单工序迁移”和 oracle upper bound；
4. 在相同 17 个有效 case 上复验，失败 case 继续保留；
5. 只有两类扩大恢复动作至少一项 paired CI 下界大于 0，才解锁恢复策略价值验证。
