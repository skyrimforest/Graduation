## 一、完成内容

### 恢复等级兼容

新输出使用：

```text
recovery_level: 0-4
recovery_action: 明确动作名
```

历史 `U0-U3` 继续作为读取兼容字段，旧 JSON、manifest 和图表不改写。

### 剩余问题

新增剩余 FJSP 问题，记录：

- 已完成、加工中和未开始工序；
- 机器状态、维修时间、剩余加工时间和最早可用时间；
- buffered、assigned、loaded transport；
- 冻结工序和可重调度工序；
- 当前时间、due date 和稳定输入 hash。

### 计划修订

初始计划和后续每次重调度都保存为计划修订：

```text
当前修订和父修订
触发事件
恢复等级
solver/image/config/seed
输入问题和 hash
机器分配、时序和运输请求
计划决策 hash
完整 artifact hash
```

计划修订账本和本地执行游标进入 Coordinator snapshot。

### CP-SAT 镜像

CP-SAT 新增无状态 `/solve`：

- 单次请求返回完整计划；
- 不修改旧服务全局游标；
- 真正使用 seed 和 worker 数；
- 支持 Job release time 和 machine available time；
- 反事实验收固定单 worker。

SkyEngine 新增 `online_fjsp` JobSolver。首次求解后，计划由 SkyEngine 本地回放，
不再逐步调用 FJSP 容器。

## 三、关键修复

1. 旧 `/init` 会消费首帧，不能用于导出完整计划；
2. 旧全局 solver 游标会污染反事实分支；
3. CP-SAT seed 和 worker 参数此前没有进入底层；
4. `env.step()` 与 `env.observe()` 曾生成不同剩余状态；
5. buffered transport 曾被错误冻结；
6. `wall_time` 导致完整响应 hash 不同，现与计划决策 hash 分离；
7. gateway URL、config 和 timeout 现已进入 snapshot。

## 四、没有完成什么

当前动态计划修订只允许查询、保存和回放，不允许激活。因为激活前必须定义：

- buffered transport 如何取消；
- assigned 但未取料的任务如何撤销；
- loaded transport 是否必须冻结；
- machine input queue 哪些任务保留；
- assigner 和 MAPF cache 如何同步失效；
- 新旧 task id 如何去重。

当前非初始修订请求 `activate=True` 会显式失败，避免重复运输物料。

因此本阶段不证明：

- 恢复等级 3 已经有效；
- 恢复等级 4 已经实现；
- CP-SAT 在线重调度改善 terminal makespan；
- DE、PSO 或 DRL 已接入；
- 可以进入因果模型、BNN 或强化学习。
