# 动态计划替换与局部排程修复验收报告

日期：2026-08-03

结论：恢复等级 3 的动态执行基础设施 Gate 通过。系统可以在机器故障时调用
真实 CP-SAT，冻结物理承诺，只替换可撤销运输，并从同一 branch point 复现
计划、激活审计和终态。

该结论不等价于“恢复等级 3 已改善 makespan”。

## 一、实现范围

### 动态计划替换

可撤销：

- JobSolver 尚未发出的未来运输；
- pending、buffered 和待分配运输；
- 已分配给 AGV 但尚未取料的运输。

保持冻结：

- loaded transport；
- machine input queue；
- 正在加工或暂停的工序；
- 已完成工序。

激活事务同时处理：

- 旧运输删除；
- 未取料 AGV 释放；
- 工序计划机器更新；
- 新 task id 分配；
- urgent reservation 清理；
- route cache 和停滞状态失效；
- 失败时环境、JobSolver 和 RouteSolver 回滚。

### 局部范围

对每个受故障影响的 Job，从最早受影响未开始工序起，开放全部尚可撤销的同 Job
后缀。这样上游机器变化后，下游运输来源会一起更新。

其它 Job 和所有物理承诺写入冻结集合。

### 执行计划语义

计划修订账本区分：

- 最新记录；
- 最近已激活执行计划；
- 只查询但未激活的计划；
- 激活失败并已回滚的计划。

只查询或失败修订不会成为下一次局部修复的父执行计划。

## 四、关键修复

1. assigned-before-pickup 曾被误判为 committed，现只有 loaded transport
   构成运输承诺；
2. Gym wrapper 直接赋值会产生 shadow state，激活器现只修改底层执行环境；
3. 初始 artifact 的本地附加字段曾破坏精确 cache replay，现只为局部修订生成
   effective schedule；
4. 查询或失败 revision 曾可能覆盖当前执行计划，现选择最近已激活 revision；
5. 取消特急运输曾可能遗留 urgent reservation，现纳入原子事务；
6. 动态验收场景曾把机器放在 padding 障碍格，现使用已验证自由格。

## 五、支持和不支持的结论

支持：

- CP-SAT 动态局部修订可以安全写回当前执行环境；
- frozen operation、loaded material 和 machine queue 不被修改；
- 可撤销运输不会重复执行；
- 激活失败不会留下半替换状态；
- 同源反事实可以复现到 terminal。

不支持：

- 恢复等级 3 在总体上优于恢复等级 0、1 或 2；
- 当前局部范围在多实例、多扰动强度下最优；
- 恢复等级 4 已实现；
- DE、PSO、DRL 已完成动态 adapter；
- 因果、BNN 或 RL 已具备启动依据。

## 六、下一步门禁

建议下一阶段只运行小规模同源 paired value Gate：

1. 固定 CP-SAT、assigner 和 liveness-guard MAPF；
2. 对同一机器故障 branch 比较恢复等级 0-3；
3. 使用 terminal makespan、完成率、求解时间和 schedule nervousness；
4. 保留全部未完成、无解和负收益 case；
5. 先判断保守局部修复是否有正向 terminal value。

在该 Gate 通过前，不进入恢复等级 4、其它 FJSP 算法、大规模实验或学习方法。
