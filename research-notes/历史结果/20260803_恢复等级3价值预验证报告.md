# 机器故障下固定局部重调度价值预验证报告

日期：2026-08-03

结论：价值 Gate 未通过。受影响 Job 的在线 CP-SAT 局部修复在工程上可靠，但
机器故障后固定触发平均增加 terminal makespan，不能进入联合完全重调度、
大规模实验或学习方法。

解释修订：运行时使用的历史 level 0、1、2 在机器故障下 60/60 产生完全相同的
物理结果，因此不能作为三个论文 baseline。本报告只比较“等待维修并继续原计划”
和“始终局部重调度”。原始数据、结果哈希和统计数值不变。

## 一、研究问题

机器故障后，始终进行受影响 Job 的局部排程修复是否比等待维修并继续原计划产生
更好的终端结果？

主比较：

```text
capped makespan(等待维修并继续原计划)
- capped makespan(始终进行局部重调度)
```

正值表示始终局部重调度更好。

## 六、工程正确性

- 局部重调度激活：60/60；
- 物料与冻结不变量：60/60；
- 历史 level 0/1/2 物理结果一致：60/60；
- duplicate delivery：0；
- canceled task 被执行：0；
- solver failure：0；
- CP-SAT wall time p95：0.0462 秒；
- FJSP 服务调用前后保持无状态。

因此主结果不能归因于 timeout、未完成 episode、重复运输或激活失败。

## 七、计划变更成本

始终局部重调度平均：

- repair scope：11.80；
- changed operations：14.48；
- machine assignment changes：4.05；
- start-time shift total：1529.83。

start-time shift 范围为 21-5304。局部修复虽然只开放受影响 Job，但仍可能产生
较大计划扰动。

## 八、后验诊断

以下分析不属于预注册主 Gate。

当前加工工序不在 clean realized critical path：

```text
39 units
mean improvement: -28.72
95% CI: [-46.23, -12.28]
```

当前加工工序位于 clean realized critical path：

```text
21 units
mean improvement: +8.24
95% CI: [-19.19, 33.38]
```

当等待维修相对 no-event 没有正 makespan loss 时，始终局部重调度平均恶化
20.98 步；当故障确实产生正 loss 时，始终局部重调度的平均效果仍接近 0。

该结果提示“是否需要干预”是主要问题之一。但 clean realized critical path 是
事后 oracle，不能直接用于在线策略，也不能包装成已验证方法。

## 九、解释

当前 CP-SAT 局部修复只优化剩余加工计划：

- 不直接消费真实运输距离和拥堵；
- 不对计划变更成本加惩罚；
- 固定触发不判断故障是否会影响 terminal makespan；
- 低强度故障可能在原计划等待或运输时间内被吸收；
- 新计划的机器改派会引入额外空载/载货路径和排程 nervousness。

因此“可行的新加工计划”不等价于“更好的端到端执行计划”。

## 十、科研结论

已支持：

1. 多实例下受影响 Job 局部重调度的执行基础设施可靠；
2. 固定进行局部重调度不具有单调价值；
3. 低强度和非关键影响下存在明显过度干预；
4. 研究问题应聚焦“何时干预、干预哪一层、使用多大范围”。

未支持：

1. 始终局部重调度总体降低 makespan；
2. 当前 CP-SAT 局部范围可作为论文正贡献；
3. 立即使用因果模型、BNN 或 RL；
4. 实现联合完全重调度；
5. 历史 level 0、1、2 是机器故障的三个有效 baseline。

## 十一、后续建议

下一阶段先补齐机器故障专属动作，不进入学习：

1. 未取料物料留在源头等待；
2. 单工序等待原机与改派成本比较；
3. 当前计划 slack 阈值；
4. 受影响 Job/Operation 数阈值；
5. 局部重调度的计划变更成本约束。

先用同一批 raw branch points 回放这些在线可观测 baseline。只有简单 gate 出现
稳定正 terminal value，才有理由研究因果干预学习。
