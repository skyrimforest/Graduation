# 机器故障在线动作选择器首轮筛选报告

## 一、回答当前问题

这一部分仍包含基础机制修正，但对象发生了变化：

- 已完成：动作语义、物理承诺、反事实分支和 terminal rollout；
- 当前问题：故障发生时的在线成本估计是否可信；
- 后续方法：只有在线信号可信后，才训练正式动作选择器。

首轮结果表明，当前在线改单工序改派估计明显失真，因此暂时不能进入复杂模型。

## 二、研究设计

复用机器故障正式实验的 60 个 paired units，策略只在以下动作中选择：

1. 等待维修；
2. 单工序改派；
3. 受影响 Job 局部重调度。

源头等待因只有 36 个 eligible units、事后 oracle 仅选中 1 次，暂不进入首个
选择器。

本轮使用 leave-one-seed-out：

- 训练折：4 seeds、48 units；
- 测试折：1 seed、12 units；
- 五折合并为 60 个 cross-fitted predictions。

## 三、防止数据泄漏

允许输入：

- 维修时长；
- branch step；
- repair scope；
- 替代工序数量；
- 机器队列和运输承诺计数；
- 动作 eligibility；
- 预计等待与改派完成时间；
- loaded distance、processing time；
- planned start/ready time 相对 branch 的 lead。

禁止输入：

- terminal makespan、TWT、OTD；
- clean/no-event outcome；
- realized critical path；
- `current_operation_on_critical_path`；
- oracle 动作；
- 测试折 outcome。

防泄漏审计通过。

## 四、成本估计器校准

| 指标 | 结果 |
|---|---:|
| 预计改派优势均值 | +4.47 |
| 真实改派收益均值 | -14.80 |
| Pearson correlation | -0.04 |
| 方向准确率 | 50.0% |
| MAE | 46.70 |

方向混淆：

- 预计正、真实正：12；
- 预计正、真实非正：21；
- 预计非正、真实正：9；
- 预计非正、真实非正：18。

因此当前估计值基本不能用于判断是否改派。

### v2 诊断估计

在保持改派 treatment 不变的条件下，v2 增加：

- AGV 完成当前任务后的最早可用时间；
- empty pickup distance；
- loaded distance；
- 替代机器 future workload；
- successor slack-adjusted impact。

| 指标 | v1 | v2 |
|---|---:|---:|
| 预计改派优势均值 | +4.47 | +3.62 |
| Pearson correlation | -0.04 | +0.05 |
| 方向准确率 | 50.0% | 51.7% |
| MAE | 46.70 | 45.35 |

v2 advantage > 0 触发改派的结果为：

- 15 win / 22 tie / 23 loss；
- mean improvement `-4.93`；
- 95% CI `[-19.12, 9.60]`。

因此仅补 empty travel、loaded travel、局部 future workload 和单后继 slack
仍不足以形成可靠端到端估计。

## Scope 规则独立验证

`mk02` 在正式 treatment outcome 运行前因 clean baseline 无法完成被整体排除，
按预注册修订记录替换为通过 10/10 clean/eligibility cases 的 Kacem `k2`。
阈值和其它实验条件未改变。

独立验证集为 `mfjs02/k2`，20 cases、60 units。Infrastructure Gate 全部通过，
但实际 `repair_scope_size` 仅为 2-10，冻结阈值 18 在 60/60 units 从未触发：

```text
selector mean improvement: 0.00
95% CI: [0.00, 0.00]
Value Gate: NOT_PASSED
```

固定改单工序诊断仍为正均值：

```text
mean improvement: +7.03
95% CI: [-7.82, 22.43]
33 win / 4 tie / 23 loss
```

因此 `repair_scope_size` 是开发实例规模代理，不能跨实例稳定选择动作。这条
scope-only 路线已停止，不在验证集重调阈值。后续 v3 估计器必须使用物理成本
分解，并保留第三组未见实例做确认。

## 六、问题解释

当前改派估计只覆盖：

```text
机器可用时间
+ loaded route distance
+ candidate processing time
```

它没有完整建模：

- AGV 到 source 的 empty travel；
- 当前路网拥堵；
- 已承诺但未进入 machine input queue 的 workload；
- 后继工序 slack 和关键区域传播；
- 改计划、撤销运输和重建运输的稳定性代价。

因此估计器可能认为“替代机器更早加工完”，但端到端系统实际因运输和下游队列
付出更大代价。

## 七、下一步

1. 在 branch point 增加时变拥堵、reservation conflict 和完整未来 workload；
2. 建模多后继 delay propagation 与 plan-change cost；
3. 先验证 estimator calibration；
4. 校准通过后冻结一个浅规则；
5. 使用未参与当前分析的新 FJSP 实例独立确认。

Gate：

- Pearson `>= 0.30`；
- sign accuracy `>= 65%`；
- selector mean improvement `> 0`；
- cluster-bootstrap 95% CI 下界 `> 0`；
- completion 和物理不变量 100%。

Causal、BNN、Offline RL 和联合完全重调度继续阻塞。
