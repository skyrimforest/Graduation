# 机器故障改派候选机器排序筛查报告

## 一、修复目标

检查当前单工序改派是否因为 v1 目标机器选择错误，限制了 v3 成本估计器的上限。

保留 v1 动作作为历史对照，新增 v3 物理成本候选排序动作。两者冻结同一工序，
只允许目标机器不同。

## 二、工程结果

- 对全部健康可达候选机器计算 v3 成本；
- v3 选择 predicted advantage 最大的机器；
- 全候选不可用时不静默退化；
- 保持 PlanRevision 与物理执行路径一致；
- 修复测试夹具的 Gym wrapper heatmap shadow state；
- 87 项 Docker 回归通过。

## 三、eligibility-only 筛查

矩阵：

- `mfjs01/mk01/mfjs02/k2`；
- maze/random；
- seeds 0-4；
- low/medium/high；
- 40 independent clusters；
- 120 severity units。

结果：

| 指标 | 结果 |
|---|---:|
| branch-point coverage | 40/40 |
| paired eligibility | 120/120 |
| multi-candidate clusters | 25/40 |
| v1/v3 disagreement clusters | 6/40 |
| disagreement instances | 3 |
| disagreement topologies | 2 |

按实例：

| Instance | Multi-candidate | Disagreement |
|---|---:|---:|
| `mfjs01` | 0 | 0 |
| `mk01` | 5 | 1 |
| `mfjs02` | 10 | 3 |
| `k2` | 10 | 2 |

## 四、Gate

预注册要求至少 10 个 independent disagreement clusters，实际只有 6 个。

虽然按 severity 展开后有 18 行，但同一 cluster 的 low/medium/high 选择完全
一致，不能视为 18 个独立决策点。

因此：

```text
Candidate Coverage Gate: NOT_PASSED
Terminal Value Experiment: STOPPED
```

没有运行小样本 terminal rollout，也没有事后降低门槛。

## 五、结论

候选机器排序机制已修复，可以安全保留为实验能力；但在当前开发矩阵中 v1/v3
机器选择高度一致，无法支撑可靠的 paired value 结论。

这说明下一层更可能的决策瓶颈是：

```text
选择哪个受影响工序进行改派
+ 为该工序选择哪台机器
```

即 operation-machine pair 选择，而非只替换目标机器排序。

Causal、BNN、Offline RL 和 CBQ-IQL 继续阻塞。
