# SkyCausal 论文实验设计章节结构（在线主实验修正版）

日期：2026-08-11

状态：论文实验章节蓝图；用于替代“以冻结快照为主实验”的旧组织方式。具体预算、样本量、
随机种子和确认集仍需通过独立可执行协议冻结。

## 一、这次修正的核心

论文的主要研究对象是：

> 在动态 FJSP-MAPF 制造系统中，当物理时钟持续推进、当前计划继续执行且未来事件仍会
> 发生时，开放式求解器元搜索能否在严格端到端时间预算内，动态选择、探测、继续或切换
> FJSP/MAPF 求解器，并安全提交对最新物理状态仍有效的计划？

因此，论文实验必须明确区分两类证据。

### 1.1 受控快照诊断

```text
加载同一个历史物理快照
冻结物理状态
让不同方法在相同输入上运行
```

用途仅限于：

```text
校准探测预算
检查短探测是否包含信息
比较预算分配器的纯算法差异
构造小规模事后虚拟最优
诊断切换和可移植解机制
```

这类实验不能支撑“系统已经满足在线动态制造要求”的主结论。

### 1.2 连续时钟在线实验

```text
动态事件发生
复制当前状态给影子求解器
物理系统继续推进
当前已提交的安全前缀继续执行
元搜索在严格墙钟预算内运行
提交前读取最新物理状态
重验证、重对齐或局部修复候选计划
只激活仍然有效的安全短前缀
```

论文的主要质量结论必须来自该实验。

### 1.3 关键边界

`600..639` 等固定种子只用于构造可复现的实验场景，不允许预先保存这些场景的最佳
求解结果。论文方法在每次事件发生后才运行，并且全部计算开销计入在线预算。

## 三、6.1 研究问题与可证伪假设

### RQ1：在线元搜索是否改善最终制造效果

在相同初始状态、相同外生事件流、相同硬件和相同端到端预算下，开放式元搜索是否优于：

```text
最佳固定求解器
固定六 profile T=1 历史基线
不做短探测的静态选择器
```

假设 H1：

> 在线元搜索能够降低完整 episode 的主要制造成本，并且收益不依赖删除失败样本。

这是论文的第一主问题。

### RQ2：短探测能否提供有效信息

检查以下早期信号是否能预测同一候选在更长预算下的效果：

```text
首次可行解时间
当前认证目标值
最优下界或最优差距
单位时间改进速度
停滞时间
失败和清理信号
```

假设 H2：

> 在开发集和独立留出集上，短探测排序与较长预算排序具有稳定关系。

该问题主要由受控快照诊断回答。

### RQ3：浅层 MCTS 是否优于简单逐轮淘汰

假设 H3：

> 在相同候选生成器、相同探测预算、相同墙钟上限和相同资源下，浅层 MCTS 优于逐轮
> 淘汰法。

若 H3 不成立，论文必须移除 MCTS，把逐轮淘汰作为最终分配器。

### RQ4：分解组合是否兼顾效果与搜索开销

比较：

```text
固定联合 profile
小规模完整 FJSP × MAPF 枚举
FJSP top-K 后条件生成 MAPF top-K
```

假设 H4：

> 分解生成能以显著更少的候选评估次数，接近小规模完整枚举的效果，并在在线环境中
> 改善端到端制造成本。

### RQ5：动态继续和切换是否存在净价值

比较：

```text
当前求解器继续运行
冷切换
传递可移植当前解的热切换
目标求解器独占完整预算
```

假设 H5：

> 至少一种状态相关切换策略在扣除停止、导出、导入、认证和清理时间后仍有正收益。

### RQ6：系统是否真正对新求解器开放

冻结控制器后增加未参与开发的 FJSP 或 MAPF 求解器，只允许新增：

```text
求解器描述文件
参数规范
适配器
少量独立校准轨迹
```

假设 H6：

> 不修改控制器固定输出维度和求解器专用分支，新求解器仍能被生成、探测、选择和安全
> 清理。

### RQ7：在线安全语义是否始终成立

假设 H7：

```text
deadline overrun = 0
遗留请求和会话 = 0
物理约束违规 = 0
无效计划激活 = 0
提交保留时间挪用 = 0
```

H7 是质量结论的前置门槛，而不是普通次要指标。

## 四、6.2 连续时钟在线决策协议

### 4.1 三个时钟

在线实验必须同时记录：

| 时钟 | 含义 |
|---|---|
| 物理时钟 | 机器加工、AGV 移动、等待和外生事件的实际推进 |
| 控制器墙钟 | 从事件触发到新计划完成激活的真实耗时 |
| 求解器预算 | 分配给各候选探测、继续或切换的时间 |

控制器墙钟和求解器预算不能被排除在物理系统之外。求解期间物理系统仍然推进。

### 4.2 单次在线决策过程

对每个动态事件，统一执行：

```text
1. 事件触发并记录 event_time
2. 原子读取当前物理状态 s(event_time)
3. 固定不可撤销前缀：
   已开始加工、载货 AGV、已进入安全关键区的路径段
4. 生成动态 SolverOption 候选
5. 在选择预算内执行短探测、继续或切换
6. 物理系统同时继续执行当前安全计划前缀
7. 在 commit reserve 开始前停止全部影子求解
8. 原子读取 commit_time 的最新物理状态
9. 对候选计划执行 freshness 和兼容性检查
10. 必要时重对齐或局部修复
11. 认证后只提交安全短前缀
12. 等待请求和会话清零，完成审计
```

### 4.3 计划新鲜度

至少记录：

```text
snapshot_age_ms
event_to_commit_ms
执行期间新增事件数
状态版本差
冻结前缀长度
重对齐是否成功
局部修复耗时
候选失效原因
最终 fallback 类型
```

不得直接激活基于旧状态产生、但未在 commit 时重新验证的计划。

### 4.4 失效后的处理

提交时若候选不再兼容：

```text
优先：在保留时间内执行有界局部修复
其次：保留当前安全前缀并提交认证 incumbent
最后：使用预注册安全 fallback
```

禁止借用 commit reserve 继续搜索。

### 4.5 公平比较的实验单位

不同方法不能同时控制同一个物理世界。公平比较采用独立数字孪生 episode：

```text
相同初始状态
相同外生事件流
相同作业到达流
相同故障和阻塞事件
不同方法各运行一个完整 episode
```

方法运行后状态轨迹允许自然分叉。统计配对单位是完整 episode 和外生随机流，不要求
不同方法在第一次决策后继续面对完全相同的内部状态。

## 五、6.3 受控快照诊断的证据边界

### 5.1 允许回答的问题

```text
同一输入下求解器轨迹是否不同
短预算排名是否能预测长预算排名
逐轮淘汰和浅层 MCTS 的纯分配差异
切换和可移植解是否正确工作
小规模完整枚举下的虚拟最优差距
```

### 5.2 禁止回答的问题

```text
系统已满足完整在线制造要求
物理继续推进时计划不会过期
在线 episode 的最终制造成本一定改善
方法可以处理任意未见动态事件
```

### 5.3 `600..639` 的重新定位

原拟议 `600..639` 快照范围降级为：

```text
开发期受控诊断候选范围
```

它可以用于预算校准和机制消融，但不能作为在线主确认集，也不能预先求出并保存线上
部署所需答案。

## 六、6.4 场景、动态事件与数据划分

### 6.1 场景维度

至少覆盖：

```text
两种以上地图拓扑
不同机器和工序规模
不同 AGV 数量
低、中、高拥堵
不同初始排程负载
```

### 6.2 动态事件

主实验至少包含：

```text
机器故障
动态作业到达
路径或通道临时阻塞
```

若首篇论文只完成机器故障，必须在标题、摘要和结论中限定，不得泛化为全部动态事件。

### 6.3 数据用途分离

建议划分：

| 数据层 | 用途 | 可否调参 |
|---|---|---|
| 历史开发 fixture | 契约、deadline、cleanup 调试 | 可以 |
| 快照诊断集 | 预算校准、短探测分析、方法筛选 | 可以 |
| 在线 pilot 集 | 检查连续时钟语义和效应方向 | 仅按协议 |
| 在线确认集 | 最终主结论 | 不可以 |
| 开放接入集 | 新求解器和新场景评估 | 不可以回流调参 |

在线确认集必须使用新的随机种子命名空间，不能复用 `600..639`。

### 6.4 信息隔离

确认集执行前冻结：

```text
方法版本
候选生成规则
预算分配器
预算网格
失败成本
主指标
样本量
统计脚本
镜像和代码校验值
```

## 七、6.5 开放求解器目录与候选方案

### 7.1 首批求解器

第一阶段：

```text
FJSP：CP-SAT、DE、PSO
MAPF：EECBS、LG-LaCAM、MAPF-LNS2
```

这些求解器用于最小闭环，不构成永久候选边界。

### 7.2 候选定义

每个候选包含：

```text
求解器身份与版本
参数配置
探测或继续预算
资源要求
支持的事件和问题规模
热启动能力
停止、导出、导入和清理语义
```

### 7.3 组合生成

避免完整笛卡尔积：

```text
状态和能力过滤
-> 生成 FJSP 候选并保留 top-K
-> 形成排程和运输需求摘要
-> 条件生成 MAPF 候选并保留 top-K
-> 端到端认证
```

小规模完整枚举只作为诊断上界。

## 八、6.6 对照方法

### 8.1 在线主对照

必须包括：

```text
最佳固定求解器或固定组合
六 profile T=1 历史基线
静态状态选择器，不做短探测
等预算轮转
逐轮淘汰法
浅层 MCTS
```

### 8.2 切换对照

```text
源求解器完整预算
目标求解器完整预算
冷切换
热切换
固定时刻切换
状态相关切换
```

### 8.3 参考上界

事后虚拟最优只能出现在受控诊断中：

```text
对同一快照完整运行全部候选
事后取最好结果
```

它不可部署，也不能作为在线方法。

### 8.4 外部方法

外部方法分成两类：

```text
原论文条件复现：放入附录或复现章节
统一在线契约比较：放入主实验
```

对应关系：

```text
No Panacea / MAG：静态状态选择器
Gray-Box Configuration：进度感知提前淘汰
Anytime Portfolio：固定或离线优化的预算计划
LNS2+RL：组合型 MAPF 候选
DSevolve：多样候选库与状态检索
```

## 九、6.7 实验组与执行顺序

### E0：契约、deadline 和清理

验证：

```text
启动、观察、停止、取消、导出、导入和清理
正常完成、协作停止和强制超时
结果认证
请求、进程和会话归零
```

不通过 E0，不运行质量实验。

### E1：受控快照轨迹诊断

目的：

```text
校准安全预算
检查短探测信息
构造小规模虚拟最优
决定是否值得比较预算分配器
```

E1 是辅助实验。

### E2：连续时钟在线基础设施 pilot

先只使用：

```text
一个动态事件
少量开发 episode
最佳固定求解器
逐轮淘汰法
安全 fallback
```

验证物理继续推进、冻结前缀、重验证、重对齐和原子提交。

E2 不用于质量结论。

### E3：在线预算分配主比较

在在线 pilot Gate 通过后比较：

```text
最佳固定
静态选择
等预算轮转
逐轮淘汰
浅层 MCTS
```

这是 MCTS 去留的主实验。

### E4：FJSP-MAPF 分解组合与切换

加入：

```text
FJSP top-K -> MAPF top-K
继续、冷切换、热切换
计划重验证和局部修复
```

### E5：开放接入与泛化

冻结控制器后加入新求解器，并评估新地图、规模、AGV 数量和动态事件。

### E6：独立在线确认

仅在 E0-E5 的方法、指标和预算全部冻结后执行。

## 十、6.8 评价指标

### 10.1 主要质量指标

```text
J_primary = episode terminal makespan
```

```text
局部修复成功率与耗时
snapshot_age_ms
每 episode 重规划次数
```

### 10.3 资源指标


## 十一、6.9 资源公平性与端到端计时

### 11.1 主计时边界

```text
开始：事件进入 controller
结束：新计划完成认证、激活且所有影子资源清理完毕
```

以下不能免费：

```text
状态复制
特征提取
候选生成
MCTS 或排序
求解器预热
探测
切换
导出和导入
重验证和局部修复
清理和审计
```

### 11.2 顺序与并行

主实验先使用固定并发上限。若比较顺序和并行模式，应作为两个独立资源制度报告，不能
把更多并行计算伪装成算法收益。

### 11.3 episode 执行顺序

不同方法在同一 seed 上的运行顺序随机化或拉丁方平衡，以减少机器负载和缓存效应。

## 十二、6.10 统计分析

### 12.1 统计单位

在线主实验的统计单位：

```text
完整物理 episode
```

快照诊断的统计单位：

```text
物理 snapshot cluster
```

二者不能混在同一个置信区间中。

### 12.2 成对设计

在线方法共享：

```text
相同初始状态
相同外生事件流
相同作业到达和故障流
相同资源制度
```

使用 episode 级成对差值。

### 12.3 主对比

预注册两个主对比：

```text
在线最终方法 - 最佳固定方案
浅层 MCTS - 逐轮淘汰法
```

若第二个对比不显著为正，最终方法改用逐轮淘汰。

### 12.4 置信区间

使用 episode cluster 级 bootstrap，报告：

```text
均值差
中位数差
95% 置信区间
胜/平/负数量
失败和 fallback 数量
```

不得只报告成功 episode。

## 十三、6.11 安全、基础设施与停止门槛

### Gate A：求解器契约

所有候选必须通过启动、停止、取消、认证和清理测试。

### Gate B：连续物理时钟

```text
求解期间物理时钟真实推进
当前安全前缀继续执行
新增事件被完整记录
```

### Gate C：提交时重验证

```text
每次提交读取最新状态
每个激活计划有 freshness audit
不兼容计划不会被激活
```

### Gate D：deadline 和静止

```text
deadline overrun = 0
活动请求和会话 = 0
commit reserve violation = 0
```

### Gate E：物理安全

```text
机器和工序约束违规 = 0
AGV 冲突 = 0
已承诺运输被撤销 = 0
```

### Gate F：方法价值

按顺序判断：

```text
候选互补性
短探测信息
逐轮淘汰价值
MCTS 相对逐轮淘汰的增量
分解组合价值
切换净价值
```

## 十九、工程实施顺序的修正

原计划把 `600..639` capture-only 作为紧邻下一步。修正后，它只是辅助轨迹校准任务，
不再是最高优先级。

新的实施顺序：

```text
1. 定义连续物理时钟、冻结前缀和提交时重验证契约
2. 实现最小 online episode runner
3. 用历史 development fixture 验证三时钟记账和安全 fallback
4. 运行少量在线基础设施 pilot，不比较算法优劣
5. 再捕获 600..639 受控诊断快照，校准探测预算
6. 比较逐轮淘汰和浅层 MCTS
7. 把冻结后的最终分配器放入在线 pilot
8. 加入 FJSP-MAPF 分解组合与切换
9. 冻结独立在线确认协议
10. 执行确认集并开始填写论文结果章节
```

在第 4 步之前，不应投入大量资源捕获快照；在第 7 步之前，不应声称元搜索已经满足
在线制造要求。
