首轮多状态探索更新：

新增的 5 个严格配对在线状态表明，短预算下 makespan-only 选择平均 regret 为 40.0，
透明 ridge Q 为 9.2，但样本量仍不足以授权 active。实验同时确认 `keep_current` 和 probe
budget 必须成为显式动作；最新状态 freshness/rebase 过滤必须先于任何学习排序。当前执行
顺序冻结为：

```text
keep current 安全动作
-> Root MCTS / 逐轮淘汰分配 probe 预算
-> probe 可行性与认证 bundle
-> 读取最新物理状态
-> 对所有 bundle 做 freshness/rebase 过滤
-> shadow/authorized Q 只排序幸存候选
-> 原子激活；无幸存候选则 keep current
```

实现收敛状态：

```text
probe 阶段 Q 不再改写 MCTS backup cost
所有认证可行 bundle 均执行 commit-time freshness/rebase
sampler 首选 stale 时允许切换到新鲜备份
只有全部幸存候选预测均获授权时才允许 active Q 排序
当前没有授权模型，实际仍使用 sampler 排序
```

## 一、文档目的

本文设计开放式 FJSP-MAPF 求解器元搜索的完整实验路线，回答四个问题：

1. 如何判断短探测和元搜索本身是否有效；
2. 如何公平比较蒙特卡洛树搜索、逐轮淘汰和其他预算分配方法；
3. 如何验证系统确实能接入未来新的 FJSP/MAPF 求解器；
4. 如何复现外部论文，并在统一条件下与本项目比较。

本文只设计实验，不授权执行。正式运行前仍需补全：

```text
真实探测预算
硬件和资源上限
样本量
随机种子命名空间
协议 JSON 及其校验值
```

## 二、主要中文术语

为减少中英文混用，本文统一使用：

| 本文用语 | 含义 |
|---|---|
| 求解器 | FJSP 或 MAPF 算法实现 |
| 候选方案 | 一个求解器、参数、预算和执行范围的组合 |
| 求解器目录 | 当前通过注册和验证的全部求解器清单 |
| 短探测 | 在小预算内影子运行候选方案，不激活物理结果 |
| 元搜索 | 对候选方案进行采样、淘汰、预算分配和选择 |
| 逐轮淘汰法 | 每轮给候选相同预算，再淘汰较差候选 |
| 浅层 MCTS | 只在当前候选方案根节点使用的蒙特卡洛树搜索 |
| 渐进扩展 | 随探测次数增加，逐步引入更多候选 |

| 最佳固定 | 在整个数据集上均值最好的单一固定候选 |
| 留出集 | 不参与配置、调参和方法选择的最终评价数据 |

## 三、总原则

### 3.1 评价的是完整系统，不是免费选择器

主实验从开始生成候选前计时，到最终结果完成认证、清理并可提交为止。

以下时间全部计入端到端预算：

```text
状态特征提取
候选生成
排序或 MCTS 计算
求解器初始化
短探测
进度轮询
停止与等待
解认证
导出与导入
切换
清理
最终审计
```

不得把元搜索、短探测或切换时间当成免费开销。

### 3.2 主评价使用同一端到端墙钟预算

主资源口径：

```text
相同端到端墙钟时间
相同硬件类别
相同最大并发服务数
相同提交保留时间
```

同时记录：

```text
求解器计算时间
服务总秒数
CPU 秒数
GPU 秒数
峰值内存
峰值并发
元搜索自身耗时
```

计算资源归一化实验只能作为单独的次要实验，不能在看到结果后改变主口径。

### 3.3 失败不能删除

主分析遵循意向处理：

```text
成功结果：使用认证后的目标值
无可行解：使用快照特定的失败上界
求解器超时：使用失败上界
求解器内部错误：使用失败上界
基础设施错误：保留样本并触发基础设施门槛失败
```

不得只报告成功分支，也不得删除使某方法变差的状态。

### 3.4 相同状态使用成对随机流

同一物理快照下，各方法共享：

```text
相同外部环境随机流
相同规划随机流映射
相同求解器随机种子规则
相同方法执行顺序随机化规则
```

求解器内部随机流与外部物理随机流分离。

### 3.5 基础设施结论优先于质量结论

以下任一项失败时，禁止给出算法优越性结论：

```text
超时记账不完整
存在遗留请求或会话
结果未完成认证
物理约束被破坏
提交保留时间被挪用
镜像或代码校验值不一致
留出数据被提前访问
```

## 四、研究问题

### 研究问题一：候选集合是否存在可利用差异

需要验证：

```text
不同状态的最佳求解器或参数是否不同；
开放候选相对最佳固定方案是否存在正向空间；
新增候选是否提供原候选集合没有的价值。
```

如果所有状态都由同一候选稳定支配，元搜索没有必要。

### 研究问题二：短探测是否能预测最终效果

需要验证短探测中的：

```text
首次可行解时间
当前目标值
最优下界和差距
近期改进速度
失败信号
清理延迟
```

与较长预算最终结果之间是否存在稳定关系。

### 研究问题三：浅层 MCTS 是否优于简单预算分配

主问题不是“MCTS 是否比随机方法好”，而是：

> 在相同候选、相同短探测预算、相同总墙钟时间下，浅层 MCTS 是否显著优于逐轮
> 淘汰法。

如果不能，保留更简单的逐轮淘汰法。

### 研究问题四：分解组合是否接近完整枚举

需要验证：

```text
先选少量 FJSP 候选
再根据排程运输特征选少量 MAPF 候选
```

能否以较少评估次数接近小规模完整组合的离线最优。

### 研究问题五：动态切换是否增加净价值

需要区分：

```text
继续当前求解器
冷切换
带可移植解的热切换
目标求解器独占完整预算
```

切换收益必须扣除停止、导出、导入、认证和清理开销。

### 研究问题六：系统是否真正对新求解器开放

冻结控制器后加入新求解器，只允许增加：

```text
求解器描述文件
适配器
参数规范
少量校准数据
```

不允许修改固定输出类别或在控制器中添加求解器专用分支。

### 研究问题七：是否能跨规模和拓扑泛化

至少评估：

```text
未见地图类型
未见 AGV 数量
未见 FJSP 规模
未见事件类型
未见求解器
```

### 研究问题八：联合制造目标是否优于组件局部目标

需要检验：

```text
MAPF 路径代价最优
FJSP 局部工期最优
```

是否真的对应最终制造完工时间最优。

```text

```

## 六、E0：契约与安全测试

### 6.1 目的

确认每个求解器能够被可靠调用和清理，不评价质量。

### 6.2 必测能力

每个求解器按其声明能力测试：

```text
启动
观察进度
继续运行
请求停止
等待停止
导出可移植解
导入初始解
原生检查点
原生恢复
清理
审计
```

未支持能力必须明确返回“不支持”，不能静默退化。

### 6.3 强制异常测试

```text
极短超时
显式取消
服务崩溃
无效输出
晚到结果
重复请求
错误配置
错误问题校验值
错误可移植解
```

### 6.4 通过门槛

```text
物理违规 = 0
遗留活动请求 = 0
遗留 MAPF 会话 = 0
晚到结果被激活 = 0
未记账超时 = 0
未声明能力调用成功 = 0
```

本层可以使用历史开发快照，不产生质量结论。

## 七、E1：单求解器轨迹校准

### 7.1 目的

确定真实短探测预算，并获取每个求解器的随时间改进曲线。

### 7.2 首批范围

先从 FJSP 开始：

```text
CP-SAT
DE
PSO
```

原因：

```text
已有进度记录
已有协作停止验证
已有可移植 FJSP 解
切换边界相对清晰
```

MAPF 在 FJSP 轨迹校准通过后再加入。

### 7.3 轨迹记录

每次运行按固定轮询间隔记录：

```text
单调时钟时间
剩余预算
是否已有可行解
当前最好目标值
最优下界
最优差距
距离上次改进时间
改进幅度
停止请求时间
最终结果就绪时间
清理完成时间
```

### 7.4 校准预算

不得直接采用单元测试中的 `10/20/40 ms`。

实际流程：

1. 在开发数据上测量首次可行解时间分布；
2. 测量协作停止和最终认证的高分位延迟；
3. 选择能覆盖不同求解阶段的 3 至 5 个预算点；
4. 保留独立的最终提交时间；
5. 在 E2 前冻结预算表。

候选预算示意：

```text
极短：覆盖快速首次可行解
短：覆盖第一轮明显改进
中：覆盖主要搜索阶段
长：接近在线总预算
```

具体毫秒数由本层数据决定。

### 7.5 输出

```text
每个求解器的首次可行解分布
目标值随时间曲线
停止和清理延迟分布
建议探测预算表
建议失败上界
不支持能力清单
```

### 7.6 通过门槛

```text
所有轨迹单调时间合法
最终解均可独立认证
停止和清理无资源残留
至少两个求解器在不同状态或预算区间占优
```

最后一项不满足时，暂停元搜索质量实验。

## 八、E2：候选空间与离线最优分析

### 8.1 目的

确认开放候选集合有选择价值，并为在线方法提供离线参考。

### 8.2 候选层次

分别研究：

```text
求解器层：算法不同
配置层：同算法参数不同
预算层：同配置预算不同
组合层：FJSP 与 MAPF 组合不同
切换层：继续、冷切换、热切换不同
```

### 8.3 小规模完整枚举

只在开发数据和受控小候选集合上执行完整枚举，用于计算：

```text
最佳固定候选
每状态虚拟最优候选
候选胜出频率
候选互补性
完整枚举成本
```

完整枚举是离线参考，不是部署方法。

### 8.4 核心指标

设成本越低越好。

最佳固定改进：

```text
最佳固定成本 - 方法成本
```

虚拟最优后悔值：

```text
方法成本 - 每状态虚拟最优成本
```

候选覆盖率：

```text
真实最佳候选出现在生成集合中的状态比例
```

前 k 覆盖率：

```text
真实最佳候选出现在前 k 个候选中的状态比例
```

### 8.5 通过门槛

开发阶段至少满足：

```text
虚拟最优优于最佳固定
胜出候选不止一个
候选生成前 k 覆盖率达到预注册门槛
候选生成开销未挤占主要求解预算
```

具体覆盖率门槛需在 E1 后冻结，不得根据最终确认结果调整。

## 九、E3：预算分配器比较

### 9.1 固定比较条件

所有分配器共享：

```text
同一求解器目录
同一候选生成结果
同一候选顺序随机化
同一探测预算表
同一总墙钟时间
同一失败上界
同一最终提交保留时间
```

只改变如何分配探测预算。

### 9.2 必要对照组

#### A：随机选择

不探测，直接从合法候选中随机选择。

#### B：最佳固定

使用开发数据上均值最好的固定候选。

#### C：均匀短探测

给所有当前候选相同短预算，再选择观测结果最好的候选。

#### D：逐轮淘汰法

每轮给存活候选相同预算，淘汰一部分较差候选。

#### E：贪心随时计划

根据开发轨迹预先形成固定求解器和预算顺序，运行时不使用 MCTS。

#### F：静态状态选择器

根据当前状态特征直接排序候选，不进行在线短探测。

第一版使用非神经方法。由于教师数据覆盖不足，当前不训练新的神经分类基线或
贝叶斯神经网络。

#### G：浅层 MCTS

使用：

```text
渐进扩展
归一化成本 UCT
渐增探测预算
失败计成本
```

#### H：离线虚拟最优

使用事后完整结果选择最佳候选，只作为后悔值下界。

### 9.3 主对照

唯一主要对照：

```text
逐轮淘汰法成本 - 浅层 MCTS 成本
```

正值表示浅层 MCTS 更好。

原因：

```text
逐轮淘汰法简单
无需复杂模型
天然适合多预算探测
是最有说服力的直接竞争方法
```

### 9.4 次要对照

```text
最佳固定 - 浅层 MCTS
均匀短探测 - 浅层 MCTS
静态状态选择器 - 浅层 MCTS
浅层 MCTS - 虚拟最优
```

次要对照不改变主要结论。

### 9.5 主要指标

```text
留出集失败封顶后的终局制造完工时间
```

### 9.6 随时性能指标

定义时刻 `t` 的认证成本 `C(t)`：

```text
首次可行解前：失败上界
首次可行解后：截至 t 的最好认证成本
```

随时曲线面积：

```text
AUC(T) = (1 / T) * 从 0 到 T 对 C(t) 积分
```

越低越好。

### 9.7 其他指标

```text
首次可行解时间
最终可行率
平均探测候选数
实际开放候选数
候选覆盖率
元搜索耗时
服务总秒数
失败率
清理延迟
```

### 9.8 保留 MCTS 的门槛

独立确认前先在试验数据上检查：

```text
相对逐轮淘汰法平均方向为正
没有增加基础设施失败
元搜索耗时稳定受控
收益不是由额外计算资源造成
```

正式确认时要求：

```text
平均改进 > 0
按拓扑分层、按快照成组的 95% 置信区间下界 > 0
全部安全门槛通过
```

若不通过，停止使用 MCTS，以逐轮淘汰法作为主方法。

## 十、E4：FJSP-MAPF 组合方法评估

### 10.1 目的

验证分解的前 k 组合是否能降低完整枚举成本，同时保留大部分质量。

### 10.2 对照

在可承担的小候选集合上比较：

```text
完整 FJSP × MAPF 枚举
固定六 profile
各自前 k 后直接组合
FJSP 排程条件下的 MAPF 前 k
分解前 k + 浅层 MCTS
```

### 10.3 组合生成步骤

```text
生成 FJSP 候选
-> 短探测 FJSP
-> 提取运输需求特征
-> 条件生成 MAPF 候选
-> 兼容性过滤
-> 联合短探测
-> 最终选择
```

### 10.4 指标

```text
相对完整虚拟最优的后悔值
最佳组合覆盖率
评估组合数量
组合生成耗时
终局制造成本
MAPF 可行率
```

### 10.5 消融

```text
不使用运输需求特征
不使用兼容性过滤
不使用分解，随机抽 joint 候选
固定 k
随预算变化的 k
```

### 10.6 通过门槛

```text
显著减少评估组合数量
最佳组合覆盖率达到预注册门槛
相对完整枚举的后悔值处于可接受范围
没有新增路径或制造物理违规
```

## 十一、E5：继续、冷切换和热切换

### 11.1 必要方法

对每个合法同域求解器对，至少比较：

```text
A 独占完整预算
B 独占完整预算
A 运行后继续 A
A 到 B 冷切换
A 到 B 热切换
```

原生检查点不支持时明确缺失，不得用重启代替。

### 11.2 主要差值

热切换价值：

```text
冷切换成本 - 热切换成本
```

切换相对继续：

```text
继续 A 成本 - 热切换成本
```

前缀对 B 的价值：

```text
B 独占完整预算成本 - 热切换成本
```

### 11.3 机制指标

```text
初始解导出成功率
热启动接受率
导入后是否保留原解质量
首次改进时间
切换总开销
最终认证成本
```

### 11.4 与当前 Two-Stage 协议的关系

现有：

```text
DE -> CP-SAT
PSO -> CP-SAT
```

仍作为首批机制验证。新的元搜索实验不得绕过当前 pilot manifest blocker，也不得
访问为其保留的 `500..559` 确认候选。

## 十二、E6：新求解器开放接入评估

### 12.1 核心实验

1. 使用现有求解器冻结候选生成器和分配器；
2. 记录控制器代码和配置校验值；
3. 加入一个新的 FJSP 求解器；
4. 加入一个新的 MAPF 求解器；
5. 只新增描述文件、适配器、参数规范和校准记录；
6. 不修改固定类别输出；
7. 在未见状态上运行。

### 12.2 首批候选

仓库已有但未进入六 profile 的候选可优先使用。

MAPF：

```text
PBS
LaCAM3
CBSH2-RTC
RHCR-style PBS
PIBT
```

FJSP：

```text
DRL
```

DRL 只作为已有外部求解器接入。当前数据覆盖门槛未通过前，不训练新的神经选择器。

### 12.3 开放性指标

```text
控制器核心代码变更行数
是否修改固定输出维度
是否新增求解器专用条件分支
新求解器契约通过率
新求解器进入候选集比例
新求解器在其离线最优状态中的选中率
加入前后虚拟最优空间变化
加入前后在线后悔值变化
```

### 12.4 通过门槛

必须同时满足：

```text
核心分配器无需修改
没有固定类别扩容
只通过公开契约接入
安全门槛全部通过
加入新求解器后系统质量不退化
新求解器有价值时能够被实际选中
```

神经模型训练需等待数据覆盖门槛通过。

### 15.2 LNS2+RL

### 15.3 Gray-Box Configuration

对应对照：

```text
基于进度的提前停止
```

第一版使用预注册规则：

```text
长时间无首次可行解
目标值明显劣于当前最好
下界或差距无竞争力
近期无改进
```

规则阈值只在校准数据上选择。

### 15.4 Anytime Portfolio

对应对照：

```text
离线固定的求解器与预算顺序
```

运行时只按计划执行，不使用 MCTS，用来判断在线自适应是否必要。

### 15.5 DSevolve

对应对照：

```text
多样候选档案 + 短探测检索
```

由于其目前为预印本，先作为探索性对照，不列为正式主要对照。

## 二十四、停止条件

出现以下任一情况，停止对应路线：

1. 候选之间没有稳定互补性；
2. 短探测无法预测长预算结果；
3. 逐轮淘汰法与 MCTS 无显著差异；
4. MCTS 收益完全由额外计算资源解释；
5. 分解前 k 长期漏掉最佳组合；
6. 热切换不优于冷切换或目标求解器独占预算；
7. 新求解器需要修改固定输出维度才能接入；
8. 基础设施失败率超过预注册上限；
9. 开放性收益只存在于用于调参的数据；
10. 跨规模或跨拓扑出现系统性安全退化。

停止 MCTS 不代表开放求解器目录失败。系统可以退回：

```text
开放目录 + 逐轮淘汰法
```

这仍然满足未来求解器开放接入要求。

## 三十、对前沿方法的中文理解与项目思考

### 30.1 No Panacea：首先承认没有万能算法

#### 原文在解决什么

随着 MAPF 求解器越来越多，不同方法在速度、解质量和次优保证上各有优劣。论文研究：

```text
面对一个具体 MAPF 问题和目标要求，
应该选择哪个求解器或配置。
```

它特别强调：

```text
只优化运行时间
在质量约束下优化运行时间
同时权衡时间和质量
```

不是同一个学习任务，不能无条件使用同一种损失函数。

#### 对我们的启发

我们的候选方案不能只写：

```text
EECBS
LG-LaCAM
MAPF-LNS2
```

而应写成：

```text
求解器
+ 参数
+ 可用预算
+ 优化目标
+ 质量或可行性要求
```

例如：

```text
EECBS，次优界 1.1，预算 500 ms
EECBS，次优界 1.5，预算 200 ms
MAPF-LNS2，邻域 8，预算 500 ms
```

这些是不同候选。

#### 我们不能直接照搬什么

```text
原文仍在固定候选集合内做选择；
主要评价是 MAPF 组件指标；
没有处理 FJSP-MAPF 制造闭环；
没有处理开放加入未知求解器；
没有覆盖我们的 deadline、cleanup 和物理提交语义。
```

#### 对项目的具体决定

```text
候选方案必须包含预算；
主要目标必须在协议中冻结；
不同目标不能混用同一训练标签；
第一版不训练固定类别神经选择器。
```

### 30.2 MAG：问题表示决定选择器能否泛化

#### 原文在解决什么

算法选择器首先需要把 MAPF 问题转换成特征。传统方式可能使用人工统计量或地图图像。
MAG 使用图嵌入表示：

```text
地图结构
障碍和通路关系
起点终点分布
智能体任务结构
```

再结合其他表示选择最优 MAPF 求解器。

#### 对我们的启发

对于 MAPF 候选初筛，状态特征至少要覆盖：

```text
地图连通结构
瓶颈和狭窄通道
AGV 密度
起终点距离分布
预测冲突数量
载货与空载比例
规划窗口
```

对于 FJSP 候选初筛，类似地需要：

```text
剩余工序数
机器柔性
负载不均衡
关键路径
故障影响范围
当前可行解质量
```

#### 我们不能直接照搬什么

```text
MAG 面向最优 MAPF 求解器；
它仍把候选看成固定类别；
只利用问题初始表示，不观察求解器中途进展；
没有处理制造调度和路径规划之间的耦合。
```

#### 对项目的具体决定

第一版先使用可审计的显式特征和简单检索：

```text
手工结构特征
+ 最近邻或树模型排序
+ 短探测验证
```

图嵌入作为后续增强，而不是首个实现 blocker。

### 30.3 LNS2+RL：不同阶段适合不同搜索组件

#### 原文在解决什么

LNS2 的核心是反复选择一部分智能体重新规划。论文发现：

```text
MARL 重规划质量较高但较慢；
优先规划速度快但合作质量较弱。
```

因此：

```text
早期使用 MARL 减少大量冲突；
后期切换到优先规划快速解决剩余冲突。
```

它说明一次求解过程中也可以存在阶段性互补。

#### 对我们的启发

长期候选不能只表示“启动哪个求解器”，还要表示：

```text
何时启动
运行多久
观察什么进展
何时继续
何时切换
切换时传递什么
何时提交
```

这正是：

```text
continue
cold switch
warm switch
commit
```

的来源之一。

#### 我们不能直接照搬什么

```text
LNS2+RL 是一个内部混合 MAPF 算法；
不是任意求解器通用调度器；
其切换发生在算法内部，状态和可传递信息已预先设计；
不能直接证明外部异构求解器切换一定有效。
```

#### 对项目的具体决定

```text
先把 LNS2+RL 视为一个原子 MAPF 求解器；
同时把“早期质量、后期速度”的思想用于外部切换研究；
外部切换必须经过 portable incumbent 和安全边界验证。
```

### 30.4 灰盒配置：不要等到终局才知道候选不合适

#### 原文在解决什么

传统黑盒配置只看到：

```text
输入配置
最终运行时间或结果质量
```

灰盒方法还读取求解器的中间输出，并用成本敏感的成对分类判断：

```text
当前运行是否明显不值得继续。
```

如果不值得，提前终止并释放资源。

#### 对我们的启发

每次短探测应记录：

```text
首次可行解时间
当前最好目标值
下界和差距
近期改进速度
距离上次改进的时间
失败和资源异常
```

这些信息不仅用于报告，还应参与：

```text
继续
停止
增加预算
切换
```

#### 我们不能直接照搬什么

```text
原文使用特定实时配置方法 CPPL；
使用成本敏感机器学习分类器；
实验领域和我们的 FJSP-MAPF 闭环不同；
不同求解器的 progress 字段未必同量纲。
```

#### 对项目的具体决定

第一版不训练进度分类器，先实现：

```text
统一进度记录
+ 预注册停止规则
+ 逐轮淘汰法
+ 浅层 MCTS
```

只有在真实轨迹证明中间特征有稳定预测力后，才训练 progress scorer。

### 30.5 随时算法组合：不同预算需要不同配置

#### 原文在解决什么

随时算法可以在不同时间停止并返回当前解。论文指出：

```text
同一个参数配置很难在所有运行时间下都最好。
```

因此它为不同预算配置不同候选组合，并提前停止不 promising 的配置。

#### 对我们的启发

在 SkyCausal 中：

```text
solver + config
```

还不够，必须增加：

```text
solver + config + budget
```

同一个求解器在：

```text
200 ms
500 ms
2000 ms
```

下应被视为不同候选或不同执行阶段。

#### 我们不能直接照搬什么

```text
原文重点是离线自动配置预算组合；
不直接处理动态制造状态；
不包含 FJSP-MAPF 组合和物理安全；
使用的 MIP 配置过程不一定适合在线决策。
```

#### 对项目的具体决定

```text
先离线校准预算网格；
在线只在冻结预算点间分配；
报告完整随时曲线，而不只报告终点；
固定预算计划作为 MCTS 的强对照。
```

### 30.6 DSevolve：保留行为多样性，而不只保留平均冠军

#### 原文在解决什么

DSevolve 面向动态柔性作业车间。它分成：

```text
离线构造多样规则库
在线根据 22 维状态特征选择规则
```

离线部分使用 LLM 引导的质量多样性搜索和 MAP-Elites，不只追求一个平均最优规则。
在线部分使用神经选择器排序规则，并部署一个当前规则。

#### 对我们的启发

求解器目录不应只保存平均成绩最好的几个候选，还应保留：

```text
擅长短预算的候选
擅长拥堵状态的候选
擅长高柔性的候选
擅长故障大范围修复的候选
擅长提供优质初始解的候选
擅长继续改进的候选
```

也就是说，候选保留标准应包含：

```text
质量
+ 行为差异
+ 状态覆盖
+ 资源特征
```

#### 我们不能直接照搬什么

```text
DSevolve 当前是预印本；
依赖 LLM 演化和神经选择器；
在线阶段仍是单规则选择；
没有我们的求解器生命周期和异构切换契约；
没有 MAPF 物理路径约束。
```

#### 对项目的具体决定

```text
借鉴多样候选档案，不立即引入 LLM；
先从现有 CP-SAT、DE、PSO 及 MAPF 求解器形成行为档案；
先使用显式状态特征和短探测；
数据覆盖门槛通过前不训练新的神经选择器。
```

### 30.7 六种思想如何组合

这六类工作解决不同环节：

```text
No Panacea
  -> 明确没有万能求解器，候选包含参数和目标

MAG
  -> 根据问题结构做第一次候选筛选

DSevolve
  -> 保持候选行为多样性

灰盒配置
  -> 利用运行中进展提前停止

随时算法组合
  -> 针对不同预算安排不同配置

LNS2+RL
  -> 允许不同搜索阶段使用不同组件
```

SkyCausal 的组合路线是：

```text
开放求解器目录
-> 状态特征初筛
-> 多样候选前 k
-> 短探测
-> 逐轮淘汰或浅层 MCTS 分配预算
-> 必要时继续或切换
-> deadline 前提交认证最好解
```

### 31.8 第一批测试


### 31.9 第一批实验 Gate

基础设施 Gate：

```text
活动请求残留 = 0
未记账超时 = 0
晚到结果激活 = 0
未认证结果提交 = 0
```

轨迹 Gate：

```text
进度时间单调
目标值只按合法方向改进
停止后无继续变异
所有缺失字段显式标记 unsupported
```

选择价值 Gate：

```text
至少两个求解器在不同 cluster 或预算区间胜出；
短探测相对随机选择有正向信息；
短探测排序不是完全不稳定。
```

如果选择价值 Gate 不通过，停止 MCTS，不进入元搜索比较。

### 31.10 第二阶段才比较预算分配器

轨迹 Gate 通过后，优先做离线回放：

```text
随机选择
均匀探测
逐轮淘汰
固定随时计划
浅层 MCTS
```

使用同一批已记录轨迹模拟预算分配，先避免重复调用大量真实服务。

离线回放只能用于：

```text
筛选方法
调试记账
选择候选参数
估算工作量
```

最终价值仍需在新快照上在线影子执行。

### 31.11 第三阶段再加入 MAPF

FJSP 元搜索确认有选择价值后，再按顺序接入：

```text
EECBS
LG-LaCAM
MAPF-LNS2
```

先做 MAPF 单组件轨迹，再做 FJSP 条件下的 MAPF 前 k，最后做联合候选。

必须先解决：

```text
session cleanup
reservation 语义
loaded transport 边界
路径可行性认证
```

### 31.12 第四阶段再加入新求解器

开放性首轮建议：

```text
MAPF：LaCAM3 或 PBS
FJSP：已有 DRL solver 仅作外部候选
```

冻结分配器后接入，验证无需修改固定输出维度。

```text
4. 补齐真实 deadline/cleanup 测试

```

在第 9 步之前，不应继续优化 MCTS 公式，也不应训练任何选择器。

## 三十二、本轮方法调研后的最终判断

最值得立即借鉴的不是某篇论文的完整模型，而是三条共同原则：

```text
候选必须多样，而不是只留平均冠军；
预算必须根据运行中证据重新分配；
复杂控制器必须先击败简单逐轮淘汰法。
```

因此项目当前主线应是：

```text
先建真实轨迹基础设施
-> 再验证短探测是否有信息
```


论文主实验必须满足：

```text
物理时钟在求解期间持续推进

执行 freshness audit

只激活认证后的安全短前缀
```

分叉，统计配对单位是 episode，而不是要求所有方法始终面对同一个冻结状态。
