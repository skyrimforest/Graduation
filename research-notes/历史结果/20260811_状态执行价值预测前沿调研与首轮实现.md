# 状态执行价值预测前沿调研与首轮实现

日期：2026-08-11

状态：首轮影子实现完成，禁止宣称已训练出有效在线价值模型。

## 一、为什么需要状态执行价值

当前浅层 Root MCTS 的动作是：

```text
下一段探测预算分给哪个 SolverOption
```

原始备份成本只使用短探测返回的 FJSP makespan。真实在线开发实验已经发现：

```text
相同 FJSP makespan
≠ 相同机器分配
≠ 相同运输与拥堵代价
≠ 相同 episode 终局时间
```

因此需要估计：

```text
Q(s, o, p, b)
```

其中：

```text
s：事件发生时的制造状态
o：solver + config + budget
p：短探测进度轨迹
b：候选产生的认证计划 bundle
```

预测目标不是“solver 自己还能把 makespan 降多少”，而是：

```text
从事件状态开始，若采用该候选计划，episode 还需要多少物理 timeline 才结束
```

第一版监督目标定义为：

```text
remaining_episode_timeline
= terminal_timeline - event_timeline
```

MCTS 仍然是浅层探测预算分配器，不展开未来制造状态树。

## 二、前沿技术调研

### 2.1 状态条件算法选择：上下文 bandit

PAK-UCB 将输入上下文作为状态、候选模型作为 arm，分别学习每个 arm 在不同上下文下的
收益，并用 UCB 处理探索和不确定性。这与本项目的结构高度一致：

```text
上下文：制造状态 + 候选计划 + probe 轨迹
arm：SolverOption
延迟收益：完整 episode 结束后的真实执行成本
```

可直接借鉴：

```text
按候选建条件价值模型
显式输出预测均值和不确定性
使用保守置信成本而不是裸均值
用在线 regret 评价选择器
```

不能直接照搬：

```text
本项目反馈延迟更长；
一次 solver 选择会改变后续制造状态；
安全约束不能被 bandit 探索绕过。
```

原文：

- PAK-UCB Contextual Bandit，ICML 2025：
  https://openreview.net/forum?id=mqDgNdiTai
- Neural Contextual Bandits Under Delayed Feedback Constraints，2025 预印本：
  https://arxiv.org/abs/2504.12086

### 2.2 Probe 进度外推：Freeze-Thaw 和多保真优化

In-Context Freeze-Thaw BO 使用部分学习曲线预测更高预算下的表现及其不确定性，并据此
决定继续、暂停或切换候选。Cost-Sensitive Freeze-Thaw 进一步直接建模“性能改善是否
值得额外成本”。

可直接借鉴：

```text
输入首次可行时间、当前目标、gap、改进速度和停滞时间；
预测再增加一档 probe 预算的边际价值；
将求解开销和候选质量放入同一 utility；
不确定时保留探索，过度自信时禁止直接淘汰。
```

当前不直接采用 FT-PFN。原因是项目尚无足够、足够多样的 solver progress 曲线来训练或
校准这种模型。第一版只保留统一轨迹特征和模型接口。

原文：

- In-Context Freeze-Thaw Bayesian Optimization，ICML 2024：
  https://arxiv.org/abs/2404.16795
- Cost-Sensitive Freeze-thaw Bayesian Optimization，NeurIPS 2025：
  https://nips.cc/virtual/2025/loc/san-diego/poster/117353

### 2.3 决策导向学习：优化真实选择 regret

Decision-Focused Learning 的核心不是让预测值在均方误差上最好，而是让预测产生的下游
决策 regret 最小。Online Decision-Focused Learning 又将这一目标扩展到随时间变化的
动态环境。

对本项目的直接启发：

```text
MAE 只能作为诊断指标；
主指标必须是 Top-1 selection regret；
训练和调参必须按状态组切分；
不能随机拆散同一状态下的不同 solver 结果；
最终必须和 makespan-only、固定 solver、逐轮淘汰比较。
```

第一版不对 MCTS 求导，也不引入可微优化层。先使用候选排序和 regret Gate，避免样本不足
时引入不必要的复杂度。

原文：

- Online Decision-Focused Learning，2025 预印本：
  https://arxiv.org/abs/2505.13564
- Decision-Focused Learning 综述，2024：
  https://arxiv.org/abs/2307.13565

### 2.4 FJSP 状态表示：异构图、运输特征和低成本下界

近期 FJSP/JSSP 工作的共同趋势是：

```text
工序、机器、作业表示为异构图；
边表示优先关系、机器可选关系、运输和时序关系；
critic/value 网络估计长期调度价值；
低成本下界作为状态价值的重要输入。
```

特别值得采用的是 2026 年状态特征设计工作提出的“低成本但有区分度的下界”思想。项目
第一版实现了透明的 undercooked completion lower bound：

```text
max(
  剩余作业最短工序链,
  剩余最短加工总量 / 机器数
)
```

它不是严格的未来制造状态模拟，只是状态执行价值的一个低成本特征。

当前不直接训练 GNN。图编码应等积累了跨实例、跨拓扑、跨事件的足够数据后，再作为线性
或树模型的替代表示进行消融。

原文：

- Framework for state features design in job shop scheduling with DRL，
  JCDE 2026：https://doi.org/10.1093/jcde/qwaf118
- End-to-End Multitarget FJSP with DRL，IEEE IoT-J 2025：
  https://doi.org/10.1109/JIOT.2024.3485748
- Offline Reinforcement Learning for Job-Shop Scheduling Problems：
  https://arxiv.org/abs/2410.15714

## 三、采用的综合架构

```text
事件状态 s
  + SolverOption o
  + probe 轨迹 p
  + 认证计划 bundle b
          |
          v
状态执行价值预测器
          |
          +-- 预测剩余 timeline 均值 μ
          +-- 认知不确定性 σ
          |
          v
风险成本 = μ + beta * σ
          |
          v
浅层 Root MCTS 备份与最终选择
```

必须保留的边界：

```text
预测器不能替代 schedule feasibility audit；
预测器不能绕过 freshness、rebase 和 activation Gate；
模型失败时回退到原 FJSP objective；
未授权模型只能 shadow，不得影响选择；
Meta Search 自身开销继续计入总 wall-clock。
```

### 4.2 特征分组

```text
作业链下界、机器负载下界、组合低成本下界
```

候选计划特征：

```text
FJSP objective

单机工序集中度
运输数量
曼哈顿运输距离

```

```text
预算和实际耗时

目标改善量
lower bound 和 gap
停滞时间
轨迹事件数和改善次数
```

SolverOption 继续通过 `solver_id`、配置、预算和 manifest 版本绑定，不增加 controller 固定
输出维度。

### 4.3 预测模型和不确定性

首个模型契约为带标准化的线性基线：

```text
预测值 =
intercept
+ solver bias
+ sum(coefficient_i * standardized_feature_i)
```

不确定性使用：

```text
residual_std
* sqrt(1 + 当前特征离训练均值的标准化距离)
```

这不是最终统计模型，只是可审计基线，用于验证：

```text
数据 schema
特征方向
模型 provenance
shadow/active 切换
不确定性风险成本
MCTS 接口
```

### 4.4 四重在线授权

预测成本只有同时满足以下条件才进入 MCTS：

```text
模型 manifest：authorization.online_selection = true
heldout_gates.passed = true
development_only = false
runner 显式 --execution-value-mode active
```

否则：

```text
仍记录 features / prediction / uncertainty
MCTS 继续使用原 probe objective
```

模型异常、字段缺失或未知 solver 均 fail closed，不得把认证 probe 误判为基础设施失败。

### 4.5 证据链

每次 probe 记录：

```text
feature_hash
model_hash
prediction_hash
backup_cost_audit
```

每个完整 episode 记录：

```text
outcome_hash
selected_feature_hash
selected_prediction_hash
remaining_episode_timeline
censored
counterfactual_complete
```

其中 `counterfactual_complete=false` 明确表示单次 episode 只观测了所选动作的真实结果。
只有同一 action-independent 状态下完成预注册候选集合的配对运行，才能形成完整监督组。

## 五、当前数据结论

现有确定性在线实验只有 3 个独立状态、15 个已执行方法结果。使用透明线性特征做
leave-one-state-out 诊断得到：

```text
Top-1 命中：1 / 3
平均选择 regret：44.7 个物理步
```

因此：

```text
当前数据证明“makespan-only 不够”；
当前数据不证明“线性 Q 已经有效”；
当前模型只能 shadow；
禁止使用这 15 条样本授权 active 模式。
```

真实 shadow 回归还观察到：相同 snapshot、solver 和 planning seed 可能产生不同认证 bundle，
对应的 episode 剩余时间也可能不同。这表示监督目标包含 solver/runtime 和后续在线执行噪声。
每个 `state × option` 必须有预注册重复，模型应预测条件分布或至少同时估计均值与不确定性，
不能把单次 outcome 当作确定标签。

## 六、训练与评估协议

### 6.1 数据单元

统计与切分单位必须是 action-independent 状态组：

```text
一个 event snapshot
× 预注册候选 SolverOption
× 预注册重复
× 完整在线 episode outcome
```

同一 snapshot 的所有候选必须位于同一个 train/validation/test 分区，禁止按行随机切分。

### 6.2 标签

主标签：

```text
remaining_episode_timeline
```

辅助标签：

```text
最终延期
AGV 运输等待
拥堵恢复次数
fallback / stale-plan / deadline 失败
计划 nervousness
```

失败候选使用预注册封顶成本，并单独报告失败分类，不允许删除。

### 6.3 模型路线

按复杂度递增：

```text
M0：makespan-only
M1：透明线性 / ridge + solver bias
M2：梯度提升树或 pairwise ranker
M3：LinUCB / kernel UCB 在线不确定选择
M4：异构图编码 + value/ranking head
M5：probe 曲线的 Freeze-Thaw surrogate
```

只有前一层通过 held-out Gate，才允许进入下一层。M4/M5 不是当前紧邻实现目标。

### 6.4 主要指标

```text
Top-1 selection regret
pairwise ranking accuracy
状态组内 Spearman 相关
相对 makespan-only 的 regret 降幅
相对最佳固定 solver 的 regret
置信区间覆盖率
模型 abstain 比例
推理 p95 / p99 wall time
```

MAE/RMSE 只能作为辅助指标。

### 6.5 Active Gate

正式阈值必须在访问独立确认集前冻结。开发阶段至少检查：

```text
按状态组 held-out；
Top-1 regret 稳定优于 makespan-only；
排序准确率的 bootstrap 置信下界高于随机；
不确定性区间不过度自信；
新 solver / 新拓扑允许 abstain；
预测 p99 开销计入预算后仍有净收益；
安全 Gate 与 shadow 模式完全一致。
```

未通过时，保留特征和 shadow 记录，MCTS 继续使用原 objective。

## 七、与主链路的关系

加入后的主链路为：

```text
事件触发
-> 开放候选生成
-> 短 probe
-> 采集 gray-box progress
-> 构造候选认证 bundle
-> Root MCTS 仅按 probe objective/progress 分配预算
-> 最新物理状态 freshness audit
-> 对所有可行 bundle 执行 rebase / repair
-> 删除 stale bundle
-> Q(latest state, option, progress, rebased bundle) 排序幸存候选
-> 原子激活
-> episode outcome 回写监督记录
```

它增强的是 commit 阶段的候选排序，不改变：

```text
开放 Solver Catalog
浅层 Root MCTS 定位
连续物理时钟
提交时重验证
安全 fallback
```

## 九、首轮多状态在线探索结果

### 9.1 探索范围

本轮只使用开发数据，不访问独立确认集：

```text
FJSP：J10P5M6
MAP：medium-mazes-seed-0000
状态 seed：53、54、55、56、57
候选：CP-SAT、DE、PSO
全预算：每个 state × solver 重复 2 次，共 30 个 episode
短预算：每个 state × solver 运行 1 次，共 15 个 episode
保持当前计划：每个 state 运行 1 次，共 5 个 episode
```

共 50 个完整在线 episode。审计结果：

```text
5/5 状态的 snapshot/problem/scope hash 严格配对
50/50 episode 结束后 solver health 通过
30/30 全预算 probe 返回可行 bundle
14/15 短预算 probe 返回可行 bundle
全预算重复的终局 target 最大极差 = 0
```

全预算重复稳定只适用于本 cohort。此前 MCTS 短 probe 曾产生不同 bundle，因此不能推广为
solver 全局确定。

### 9.2 求解器互补性成立

全预算下的终局 timeline：

| seed | CP-SAT | DE | PSO | 最优集合 |
|---|---:|---:|---:|---|
| 53 | 439 | 482 | 425 | PSO |
| 54 | 508 | 490 | 490 | DE、PSO |
| 55 | 535 | 518 | 540 | DE |
| 56 | 578 | 595 | 590 | CP-SAT |
| 57 | 540 | 578 | 578 | CP-SAT |

三个 solver 都至少在一个状态进入最优集合。因此：

```text
不存在当前 cohort 上始终支配其他候选的单一 solver；
状态条件选择具有真实 headroom；
固定平均冠军不能替代状态选择器。
```

### 9.3 长 probe 可能降低在线质量

`seed57` 中：

```text
CP-SAT 约 0.35 秒返回，物理推进 0 步，可安全激活；
DE/PSO 约 3.3 秒返回，物理推进 3 步；
repair scope 在此期间改变；
DE/PSO bundle 均因 repair_scope_changed 和 transfer_scope_changed 被拒绝；
安全 fallback 结束于 timeline 578。
```

对全预算与短预算结果比较：

```text
15 个 state × solver 中：
10 个短预算更好
3 个相同
2 个更差
```

典型结果：

```text
seed54 DE：490 -> 468
seed55 DE：518 -> 492
seed56 DE：595 -> 528
seed57 CP-SAT：540 -> 478
```

这证明：

```text
solver + budget 必须共同构成动作；
更多求解时间不保证更高在线价值；
求解期间物理漂移必须进入价值和安全判断。
```

### 9.4 keep current 必须是显式动作

新增不启动 meta search、不修改当前安全计划的 `keep_current` 基线。结果：

| seed | 保持当前计划 | 最佳短预算动作 | 最佳终局 | 改善 |
|---|---:|---|---:|---:|
| 53 | 433 | keep current | 433 | 0 |
| 54 | 500 | DE / PSO | 468 | 32 |
| 55 | 517 | DE | 492 | 25 |
| 56 | 570 | DE / PSO | 528 | 42 |
| 57 | 578 | CP-SAT | 478 | 100 |

短预算 oracle 相对始终保持当前计划平均减少：

```text
39.8 个物理步
```

但 seed53 中任何已激活的新计划都不优于 keep。故动作空间应为：

```text
keep current
+ solver
+ config
+ probe budget
```

不能在事件触发后强制选择一个 solver bundle。

### 9.5 makespan-only 在短预算下失败

短预算下按最小 FJSP makespan 选候选：

```text
Top-1：0 / 5
平均 selection regret：40.0
```

典型反例：

```text
seed57：
CP-SAT makespan = 50，终局 timeline = 478
DE/PSO makespan = 41，终局 timeline = 532
```

因此较低 FJSP makespan 可能对应更差的在线闭环结果。

### 9.6 价值特征有初步信号，但未通过 active Gate

在短预算可行候选上，使用 45 维特征做严格 leave-one-state-out：

| 方法 | Top-1 | 平均 regret |
|---|---:|---:|
| makespan-only | 0 / 5 | 40.0 |
| 最佳固定 DE | 3 / 5 | 12.0 |
| 透明 ridge Q | 3 / 5 | 9.2 |
| 状态交互 ridge Q | 3 / 5 | 12.0 |
| 成对排序 Q | 3 / 5 | 12.0 |

透明 ridge 在可行 solver 间命中 4/5，但 seed53 的真实最优动作是 keep，因此完整动作空间下为
3/5。它在 seed54 仍产生 40 步 regret。

正确结论：

```text
执行特征明显优于裸 makespan，值得继续采集；
复杂交互模型尚未优于简单模型；
5 个状态不足以授权任何 active Q；
当前只能 shadow。
```

### 9.7 修正后的策略顺序

本轮证据支持以下在线顺序：

```text
1. 将 keep_current 放入正式候选；
2. probe 后先删除无可行解的候选；
3. 读取最新物理状态；
4. 对所有候选执行 freshness/rebase preflight；
5. 删除 stale bundle；
6. 用 Q(state, option, progress, bundle) 排序剩余候选；
7. MCTS 只负责分配 probe 预算；
8. Q 未通过 Gate 时继续使用 shadow，不影响执行。
```

freshness/rebase 是确定性安全检查，优先于学习预测。不能让 Q 覆盖或绕过它。

## 十、策略顺序实现收敛

2026-08-11 图表版完成后，对在线控制器进行了实现层复核并修正两处顺序问题。

修正前：

```text
Q 可能在 probe 阶段改写 MCTS backup cost
-> sampler 先选一个 bundle
-> 只对该 bundle 做 freshness/rebase
-> stale 时直接 keep current
```

修正后：

```text
probe Q 只记录证据，不改变 solver objective
-> Root MCTS / 逐轮淘汰只分配 probe 预算
-> 收集本轮每个 option 的最佳认证 bundle
-> 读取最新物理状态
-> 对所有认证 bundle 执行 freshness/rebase
-> sampler 首选仍新鲜时保持原选择
```
