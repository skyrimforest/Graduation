# SkyEngine 实验实施方案

## 1. 最小可运行版本

先不要实现完整的三创新点。第一阶段只实现一个可复现的闭环环境：

1. 一个小型网格车间，包含 3–5 台机器、2–4 台 AGV、5–10 个工件；
2. 一个 FJSP 规则或简单求解器产生下一道工序和目标机器；
3. 一个 MAPF 求解器产生无碰撞路径；
4. 一个事件驱动仿真器推进到下一个加工完成、运输到达或阻塞解除事件；
5. 记录 makespan、运输时间、等待时间、冲突次数、机器利用率和 AGV 利用率。

验收标准：同一个 seed 能复现完整 episode；路径冲突会增加到达时间；到达时间变化会改变后续机器/工件状态；所有指标可以由日志重新计算。

## 2. 基线矩阵

至少包含以下基线：

| 类别 | 基线 |
|---|---|
| 调度规则 | FIFO、SPT、MWKR、最短运输距离、负载均衡 |
| 分配规则 | 最近 AGV、最早可用 AGV、最短预计完成时间 |
| 单专家 | 每个 FJSP/MAPF 组合单独运行，不做学习融合 |
| 学习基线 | BC、PPO 或 DQN、单专家蒸馏 |
| 联合基线 | 静态运输时间矩阵、带运输感知的 FJSP、闭环但固定规则 |
| 上界/小规模基线 | CP-SAT、MILP 或穷举/最优解（仅小规模） |

如果暂时无法接入复杂 FJSP 求解器，先用规则基线完成闭环验证；但论文最终不能只比较 FIFO 和最近邻。

## 3. 必做消融实验

### A. 闭环有效性

- 静态运输时间 vs. 显式 MAPF 路径执行；
- 单向 FJSP→MAPF vs. 双向反馈；
- 有阻塞反馈 vs. 无阻塞反馈；
- 真实路径冲突 vs. 只统计理论最短路。

### B. 多专家机制

- 单个最好专家；
- 固定平均权重；
- 固定验证集权重；
- 状态依赖权重但无 rollout；
- 状态依赖权重 + rollout-relative supervision；
- 完整方法去掉在线更新。

### C. 泛化能力

- 训练/测试规模不同；
- 训练/测试 AGV 数量不同；
- 未见过的地图拓扑；
- 未见过的 FJSP × MAPF 算法组合；
- 低、中、高拥堵强度；
- 新工件到达、机器故障和运输延迟。

## 4. 指标体系

### 主要结果指标

- Makespan；
- 平均完工时间和总延期；
- 相对于最强基线的 gap；
- 可行率/死锁率；
- 单 episode 推理时间。

### 耦合诊断指标

- AGV 等待时间占比；
- 机器因物料未到而饥饿的时间；
- AGV 空载率和平均负载率；
- 路径冲突、重规划和绕行次数；
- 阻塞事件数量与平均持续时间；
- 从 AGV 阻塞到机器/工件延迟的传播时间；
- 重调度次数和每次重调度的收益。

不要只报告 17 个指标的总表。主表保留 4–6 个核心指标，其余指标放在附录或诊断分析中。

## 5. 训练数据和数据泄漏控制

- 按实例和地图划分 train/validation/test，不能按 episode 随机切分同一实例；
- 专家轨迹只用 train 实例生成；
- 未见算法组合必须在测试时才出现；
- 每个主要结果至少使用 5 个随机种子，报告均值和标准差；
- 记录环境版本、配置、随机种子和硬件时间。

## 6. 推荐实施顺序

### Phase 1：环境正确性

完成 FJSP 状态机、网格路网、AGV 路径执行、碰撞/等待处理和日志回放。

### Phase 2：规则基线

实现最近 AGV、最早可用 AGV、最短预计完成时间，并完成静态/闭环对比。

### Phase 3：组合实验框架

实现 FJSP solver 和 MAPF solver 的 registry、统一接口、配置文件和批量评测。

### Phase 4：学习 Assigner

先做 BC，再做在线 rollout 修正，最后实现状态依赖专家权重。不要一开始同时实现 BC、DAgger、GRPO 和多专家网络。

### Phase 5：泛化与论文表格

固定测试协议后再跑完整矩阵，生成 CSV、置信区间、消融表和可视化轨迹。

## 7. 结果表的最低设计

至少准备四张表：

1. 总体性能：不同方法在主要测试集上的 makespan、延期、可行率；
2. 闭环收益：静态/单向/双向环境的耦合指标；
3. 消融实验：去掉专家可靠性、rollout、在线更新和路径反馈；
4. 泛化实验：规模、地图、AGV 数量、拥堵强度和算法组合外推。

每张表都要注明实例数量、seed 数量、是否使用相同计算预算，以及“越低越好/越高越好”。
