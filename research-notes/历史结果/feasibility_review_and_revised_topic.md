# SkyEngine 科研设想审查与改题建议

**审查日期：2026-07-12。审查立场：以严格审稿人/立项答辩标准判断，而非为既有设想寻找包装。**

## 一、直接结论

原设想的完整版本——“FJSP-MAPF 统一环境 + 多专家在线蒸馏 + student-induced states + GRPO + 专家增强多塔网络”——**不建议作为当前单篇论文的执行方案**。

原因不是问题没有价值，而是它同时存在新颖性、可证伪性和工程可交付性三方面风险：

1. **方向已拥挤。** 2025–2026 已有 FJSPT/FJSP-AGV 的图注意力、协作 MARL、Transformer 双智能体和动态扰动 DRL 工作。只要论文主要结论是“联合机器/AGV 决策 + GNN/RL 优于规则”，新颖性很弱。
2. **方法链条不自洽。** FJSP 求解器、MAPF 求解器与 Assigner 的动作粒度不同：FJSP 可能输出完整或局部排程，MAPF 输出路径，Assigner 输出任务–AGV 匹配。它们不能直接被称为在同一动作空间内可加权蒸馏的“专家”；需要额外定义共同的决策接口和反事实标签，否则“多专家”只是名称。
3. **GRPO 缺乏问题驱动。** GRPO 是相对回报的策略优化技术；若没有清楚的候选组、优势估计、信用分配和与 PPO/离线 RL 的严格对照，把它搬到调度问题会被审稿人视为术语堆砌。
4. **环境贡献尚未成立。** 当前 `SkyEngine` 主要是注册器、日志和数据骨架，尚无可回放的 FJSP–AGV–路径事件闭环。没有环境验证，无法声称“统一环境”是研究贡献。
5. **范围严重超载。** 你同时承诺环境、多个算法服务、学习框架、网络创新、理论链条与大实验矩阵；任何一个环节没跑通都会让整篇论文没有结果。

因此：**保留现有 FJSP/MAPF 仓库和 SkyEngine 名称，但放弃第一版的多专家蒸馏/GRPO主线。** 它们可以作为第二篇论文或完整平台成熟后的扩展。

## 二、为什么不是简单“继续做 FJSP-AGV RL”

近期工作已覆盖以下组合：

- FJSPT 的 GAT/MARL 联合机器、工序和 AGV 选择；
- FJSP-AGV 的协作深度强化学习；
- Transformer 双智能体 FJSP-AGV；
- 随机 FJSP 的场景建模与风险目标；
- 学习引导的 FJSP 滚动时域优化；
- 直接在 CP 中联合表达车间调度与运输路由。

所以“多智能体/图网络/AGV/强化学习/多目标”本身均不能构成创新点。真正仍未被充分验证、并且与你现有两个算法仓库天然匹配的切口是：**调度时使用的运输时间估计，怎样因 MAPF 的真实执行、拥堵和重规划而失效；如何只在必要时用昂贵的 MAPF 反馈触发重调度。**

## 三、建议的新题目

中文题目：

> **面向路径执行不确定性的闭环滚动柔性车间调度：MAPF 驱动的风险感知运输时间预测与选择性重调度**

英文题目：

> **Risk-Aware Closed-Loop Rolling-Horizon Scheduling for Flexible Job Shops with Explicit Multi-Agent Path Execution**

### 一句话问题定义

FJSP 调度器把运输时间当作固定常数会导致计划与实际路径执行脱节。我们能否从实时车间–路网状态预测运输时间的分布/风险，并只在高风险时调用 MAPF 和重新优化，以在同等或更低计算预算下减少延期、机器饥饿与拥堵传播？

### 该题的三个可落地贡献

1. **闭环基准环境（系统贡献，非唯一卖点）**：事件驱动地连接现有 FJSP 与 MAPF 服务，使真实路径执行回写工件到达、机器释放和 AGV 状态。
2. **路径时延风险模型（方法贡献）**：对每个候选运输任务/机器选择，预测路径执行时延的均值与上分位数（或 CVaR），输入包括距离、AGV 位置、队列负载、局部瓶颈、路网拓扑和冲突历史。
3. **风险触发的滚动重调度（决策贡献）**：把预测的风险运输时间输入 CP-SAT/滚动时域调度；仅在预测风险超过阈值、实际偏差异常或关键机器饥饿风险高时，调用精确 MAPF 并重优化。

这个题的关键不在“训练一个更复杂网络”，而在于证明：**少量、选择性的 MAPF 闭环查询，比静态时间估计和每步全量重规划更有效。**

## 四、研究假设与可证伪实验

| 假设 | 对照 | 成立证据 |
|---|---|---|
| H1：静态时间会系统性低估拥堵时延 | 静态最短路 vs 真实 MAPF 执行 | 高拥堵下到达时间误差、机器饥饿和 makespan 显著增加 |
| H2：风险预测改善重调度决策 | 均值预测/静态时间 vs 分位数或 CVaR 预测 | 在同 MAPF 调用预算下降低 CVaR/makespan/延期 |
| H3：选择性重规划优于两个极端 | 从不重规划 vs 每次事件都重规划 | 质量–计算成本 Pareto 前沿更优 |
| H4：结论可迁移 | 未见地图、AGV 数量、拥堵强度、FJSP 实例 | 性能退化小于静态和纯规则基线 |

## 五、必须先做的反证实验（两周内）

先回答一个问题：**真实 MAPF 反馈是否足够强，值得形成论文？**

1. 建一个小型地图（窄通道、共享交叉口）和一个开阔地图；
2. 运行相同 FJSP 决策，在静态距离矩阵和真实 MAPF 执行两种模式下对比；
3. 逐步增加 AGV 数、任务密度和跨区运输比例；
4. 测量计划–实际运输时延误差、机器饥饿、AGV 等待、makespan；
5. 若高拥堵下没有明显差异，则当前 MAPF 耦合不是论文主线，应转为纯 FJSPT/资源分配题目。

该反证实验的产出决定是否继续整个项目；不要先做深度学习。

## 六、6–8 周可执行计划

### Phase A（第 1 周）：接口与回放

- 审计 `SkyEngine-FJSP`、`SkyEngine-MAPF` 的 HTTP API、数据格式和单位；
- 在 `SkyEngine` 建立 adapter，不修改两个算法仓库核心代码；
- 定义统一事件日志：`schedule_decision`、`transport_created`、`agv_assigned`、`path_planned`、`wait/block`、`transport_arrived`、`operation_started`；
- 完成固定 seed 的 episode 回放。

**交付：** API contract、最小 demo、JSONL 日志。

### Phase B（第 2 周）：反证与规则基线

- 实现静态距离、真实路径、最近 AGV、最早可达 AGV 四个基线；
- 完成 H1 的拥堵敏感性实验；
- 只有结果显示静态估计确实失效时才继续。

**交付：** 1 张主图 + 1 张汇总表 + 是否继续的决策记录。

### Phase C（第 3–4 周）：风险模型

- 用真实 MAPF rollout 生成监督数据；
- 构造任务–AGV–路网特征，先从 LightGBM/MLP 分位数回归开始，不要先用 GNN；
- 预测运输时延中位数及 P90，校准覆盖率；
- 基线为欧氏/最短路距离、历史均值和仅均值回归。

**交付：** 误差、分位数校准和跨拥堵泛化结果。

### Phase D（第 5 周）：风险感知滚动重调度

- 将预测 P90/CVaR 运输时间写入 FJSP 的 CP-SAT 或启发式代价；
- 实现三个触发器：预测高风险、实际偏差、关键机器饥饿；
- 每次触发才查询 MAPF 并滚动重优化；
- 设定严格的每 episode MAPF 调用预算。

**交付：** `never / always / risk-triggered` 三组可运行策略。

### Phase E（第 6–7 周）：完整评测与消融

- 规模、AGV 数、地图、FJSP 实例、拥堵强度外推；
- 消融：无风险（均值）、无校准、无选择触发、无路径反馈；
- 5–10 seeds，报告均值、标准差、置信区间和失败率。

**交付：** 四张论文表、Pareto 图、典型轨迹可视化。

### Phase F（第 8 周）：论文与复现包

- 按系统论文结构写作：问题、环境、风险模型、策略、实验、局限；
- 发布实例清单、配置、命令、日志样例和结果 CSV；
- 将原“多专家蒸馏”移到 Future Work，不作为主贡献。

## 七、给后续执行模型的任务顺序

按顺序发送，任一步未验收不要跳步：

1. **审计任务：**“阅读 `SkyEngine`、`SkyEngine-FJSP`、`SkyEngine-MAPF` 的 README、Docker 和服务代码；输出 API contract 表，不改代码。”
2. **环境任务：**“仅在 `SkyEngine` 新建 `integration/`，实现 FJSP/MAPF adapter 与事件数据模型；提供一个不依赖 GPU 的端到端 mock demo 和单元测试。”
3. **基线任务：**“实现静态运输时间与真实 MAPF 执行两种模式，加入最近 AGV/最早可达 AGV；输出逐事件 JSONL 与 episode CSV。”
4. **反证任务：**“设计 2 地图 × 3 拥堵水平 × 5 seeds 实验；生成 H1 结果表和图，不训练任何神经网络。”
5. **预测任务：**“基于日志构造运输时延数据集；完成最短路、历史均值、分位数回归三种预测器及校准评估。”
6. **滚动优化任务：**“实现 risk-triggered 重新规划，比较 never/always/risk-triggered，所有策略使用相同 MAPF 查询预算。”
7. **论文任务：**“依据 CSV 自动生成主表、消融表和图，并将真实数字填入 `论文/article.tex`；禁止手填结果。”

## 八、何时放弃该新题

在 Phase B 后满足任一条件即停止：

- 真实路径执行相对静态时间没有可重复的影响；
- MAPF 服务无法提供稳定、可解释的多 AGV 冲突/等待数据；
- 运行时间使得每个实验矩阵无法在可接受时间内完成；
- 静态距离加简单规则已经全面接近全量重规划结果。

这种情况下，不应强行做 RL。可改为“不同 FJSP 与 MAPF 算法组合的系统性基准与失效模式研究”，将重点放在可复现 benchmark、实例生成和耦合诊断指标。

## 九、前沿依据

- L-RHO（ICLR 2025）已证明学习引导滚动时域优化是 FJSP 的有效前沿路线；
- AAAI 2025 的随机 FJSP NCO 说明不确定性和风险目标是有价值的研究主线；
- 2025–2026 的 FJSPT/FJSP-AGV 工作已广泛使用 GNN、注意力、MARL、Transformer 与联合决策；
- 2026 的 CP 路由–调度整合工作说明调度与运输同步建模正在成为明确研究方向。

这也是为什么建议把创新压到“MAPF 路径执行不确定性 + 风险触发闭环重调度”，而不是重复“GNN/MARL 联合调度”。
